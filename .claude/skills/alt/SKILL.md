# Тыкалка

Владелец хочет показать пальцем, а не описывать словами. Дальше — как
это включить, как читать показанное и как выключить.

## Как включить

1. **Поднять стек, если он не поднят:** `make up`.
2. **Запустить тыкалку в фоне:** `make work`.
   Она гасит Caddy и поднимает дев-сервер на **том же адресе** `:8477` —
   специально, чтобы владелец не менял вкладку.
3. **Дождаться строки `ready in` в выводе** — до неё адрес не отвечает.
4. Сказать владельцу ровно это, коротко:

   > `http://localhost:8477` — зажми **Alt**, наведи, щёлкни.
   > **Enter** — записать, **Escape** — отмена.

## Пока он тыкает

**Не запускай `make test-ui` и `npm run test-ui`.** Собранного образа
на 8477 сейчас нет — там дев-сервер, и проверки либо не пройдут, либо
солгут зелёным по неправильной сборке. Сперва `make up`.

Не поднимай второй дев-сервер: порт занят, и Vite упадёт с «Port 8477
is already in use». Если это случилось — сервер уже работает, проверь
`curl -s -o /dev/null -w "%{http_code}" http://localhost:8477/`.

## Как читать замечания

Они копятся в **`dock/reference/ui-notes.md`**. Одна запись — один щелчок:

```
## текст владельца
- **где:** Rail › RoomList › SidebarSection › ChannelRow
- **что:** <button> — «Смета»
- **классы:** flex min-w-0 flex-1 items-center …
- **когда:** 10.09.2026, 19:24:44
```

**Цепочка компонентов — это адрес.** По ней открывается нужный файл.
Классы — вторая подсказка: по ним находится точная строка внутри файла
одним поиском.

⚠️ **Текст владельца короток и часто без подлежащего** — «вот тут скрол
есть его нужно не отображать», «менее заметно». Это не небрежность:
он показывает пальцем, палец уже сказал «где». Не переспрашивай «а что
именно вы имеете в виду», если цепочка компонентов отвечает на это сама.

⚠️ **Читай файл целиком перед разбором.** Замечаний бывает десяток
подряд, и последние отменяют первые: «сделай меньше» → «ещё меньше» →
«верни как было». Отработав их по одному сверху вниз, ты сделаешь работу,
которую владелец уже отменил.

## Как чинить

Каждое замечание — обычная правка, и правила те же, что всегда: сперва
арбитр, потом код. Для вида арбитр — это гейт (контраст, ритм, цвет
из токена) либо сценарий интерфейса; «стало красивее» доказательством
не считается.

⚠️ **Разобранное замечание помечай прямо в файле** — строкой `✅ сделано`
под записью. Иначе на следующем включении ты разберёшь его второй раз.

## Как выключить

`make up` — возвращает собранный образ на тот же адрес. **Сделать это
обязательно перед проверками интерфейса** и перед тем, как сказать
«всё зелёное».

## Находки

1. **Heym, «Spec Driven Development: What Our Agents Ignored», 21.08.2026** ✓
   <https://heym.run/blog/spec-driven-development> — 1133 коммита за 117 дней против
   AGENTS.md на 203 строки. Правила, называющие файл, каталог или запрещённый образец, —
   100% соблюдения. Предел размера файла нарушен в 31% файлов: у правила-свойства нет
   момента, когда одна правка его ломает, и агент нарушения не замечает.
   **Нам:** правило-свойство («до 800 строк», «спека синхронна», «план был») держит
   только гейт; прозе остаются правила вида «одна правка ломает».
2. **jacoelho, «Spec tools and hooks: what they automate», 09.2026** ✓
   <https://www.jacoelho.com/blog/2026/09/spec-tools-and-hooks-what-they-automate/> —
   в OpenSpec `verify` не блокирует `archive`; хук-уведомление ничего не доказывает,
   блокирует только отказ.
3. **OpenSpec 1.13.0–1.13.2, 09–23.09.2026** ✓ <https://github.com/Fission-AI/OpenSpec/releases> —
   `apply` предупреждает об изменении без дельты, `status --all`, `show --diff`,
   `validate --report findings`, починен CRLF (у нас Windows).
4. **Spec Kit 1.0.x, команда converge** ✓/◐ <https://github.com/github/spec-kit/releases> —
   обязательные хуки событий (`optional: false`), сверка кода со спекой, CI Guard.
   **Нам:** только идея сверки, сам набор — четвёртый дом документов, не брать.
5. **fiberplane/drift** ✓ <https://github.com/fiberplane/drift> — связь «документ ↔ символ
   кода» хешем AST; `drift check --changed` краснеет, если символ изменился, а документ нет.
   Кандидат на «спека синхронна»; новая зависимость — только с согласия владельца.
6. **Cross-model review, arXiv 2607.21656, 22.07.2026** ✓ <https://arxiv.org/html/2607.21656v1> —
   ревью другой моделью помогает не всегда: одно направление 71.6 → 89.7%, обратное
   91.4 → 82.8% (ревьюер переписывал код целиком). Самоизучение той же моделью — без изменений.
7. **open-code-review** ✓ <https://github.com/alibaba/open-code-review> — детерминированный
   выбор файлов и правил, решает модель. **Оговорка к Р-046:** в режиме делегирования
   ревьюер — та же модель, что писала код (см. п. 6).
8. **Probity / TDD Guard** ✓ <https://github.com/nizos/probity> — политики для Claude Code:
   `enforceTdd`, `requireCommand`, запрет образцов команд и содержимого. Дыра: красный тест
   в субагенте блокирует зелёную фазу (issue #80). Готовое «красный тест до кода»;
   новая зависимость.
9. **Хуки Claude Code** ✓ <https://code.claude.com/docs/en/hooks> — блокирует только
   `permissionDecision: "deny"` или код 2; любой другой ненулевой код НЕ блокирует.
   Событие `InstructionsLoaded` показывает, какие правила реально попали в контекст.
10. **Skill Lift, arXiv 2608.20614, 24.08.2026; Tessl Task Evals** ✓
    <https://arxiv.org/pdf/2608.20614> — польза скилла = прогон с ним минус прогон без него;
    частота срабатывания меряется, неработающий 30 дней скилл переписывают или удаляют ◐.
11. **TDAD, arXiv 2603.17973** ✓ <https://arxiv.org/html/2603.17973v1> — инструкция
    «делай TDD» прозой УВЕЛИЧИЛА регрессии (9.94% против 6.08%); карта «какие тесты задевает
    правка» — 1.82%. Короткий скилл лучше длинного.
12. **Тесты агента, arXiv 2602.07900; over-mocking, MSR'26 2602.00409** ✓ — тесты, которые агент
    пишет сам, почти не меняют исход и перегружены подделками.
13. **Spec-driven test generation, arXiv 2608.17177** ✓ — сначала контракт (пред- и постусловия),
    потом тесты: +9.8 п.п. найденных багов.
14. **Kiro, property-based тесты из спеки** ✓ <https://kiro.dev/blog/property-based-testing/> —
    критерий приёмки → свойство, fast-check для TypeScript.
15. **ImpossibleBench (ICLR 2026) ◐; The Verification Horizon, arXiv 2606.26300 ✓** — при тесте,
    противоречащем спеке, модели правят тест; повтор с обратной связью жульничество не снижает.

## Механизмы: из текста в проверку

1. Строки «план / тест / спека / ревью» в сообщении коммита — проверяет хук и `make check`
   (**взято в task-116**, тот же приём, что у карты).
2. Сторож ослабления тестов по диффу — `test-not-adjusted` из AQK 0.17 (обвязка `checkwash`,
   новая зависимость — вопрос владельцу).
3. PreToolUse «красный до кода» — Probity `enforceTdd` (новая зависимость — вопрос владельцу).
4. Журнал `InstructionsLoaded` и вызовов скиллов — меряем, что агент реально читал.
5. Связь спеки с кодом хешем — `drift` (новая зависимость — вопрос владельцу).
6. Ревью с отметкой «подтверждено / отклонено» по каждому замечанию — доля подтверждённых
   меряет ревьюера.

## Не брать

- Spec Kit поверх OpenSpec — четвёртый дом документов (Böckeler,
  <https://martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html> ✓).
- Spec-as-source (Tessl framework) — негибко и недетерминированно.
- Длинные скиллы-процедуры TDD — по TDAD вредят.
- Кросс-модельное ревью без запрета переписывать код — в замере ухудшало.
- Агентские тесты как доказательство — нужен тест через внешнюю границу.
- Хуки-уведомления — не блокируют, ничего не доказывают.

# Plane и Huly — разбор

> ⚠️ **Важная поправка.** У нас скачаны **не исходники, а комплекты развёртывания**:
> у plane — 3 файла (`docker-compose.yaml`, `plane.env`, `setup.sh`), у huly — 140
> (compose, helm, nginx, скрипты бэкапа). Прочитать их код нельзя. Всё ниже — по
> инфраструктуре, их собственной документации и отзывам из сети.

Оба — **обычные трекеры без агентов**. В бизнес-ТЗ они названы главной развилкой В-1,
и разбор нужен, чтобы понять, что именно они дают и чего стоят.

---

## Plane

| | |
|---|---|
| Звёзд | ~58 400 |
| Язык | TypeScript 70% · Python 27% |
| Лицензия | **AGPL-3.0** ⚠️ |
| Версия в комплекте | v1.4.2 |

### Что разворачивается

Шесть своих сервисов: `web` (основное приложение) · `space` (публичные страницы) ·
`admin` (админка) · `live` (совместное редактирование в реальном времени) · `api` ·
`worker` + `beat-worker` (фон и расписание) · `migrator`.

Чужое: **PostgreSQL 15.7** · **Valkey 7.2** (ответвление Redis) · **RabbitMQ 3.13** ·
**MinIO** (файлы) · собственный `proxy`. Итого около **двенадцати контейнеров**.

Все сервисы масштабируются числом копий отдельно (`WEB_REPLICAS`, `API_REPLICAS`,
`WORKER_REPLICAS` и т. д.) — то есть рассчитаны на рост.

### Плюсы

- зрелый и опрятный трекер: задачи, проекты, циклы, модули, пять раскладок доски,
  наборные фильтры, можно включать и выключать функции;
- **сертификации** SOC 2, ISO 27001, GDPR, HIPAA, CCPA — независимо проверены;
- ставится одной командой, есть своя утилита командной строки для обновлений,
  бэкапов и наблюдения;
- низкий порог: после установки можно сразу работать, без долгой настройки;
- заявлены агенты для помощи с задачами и автоматизации.

### Минусы

- ⚠️ **AGPL-3.0.** Сетевой сервис, построенный на его основе, обязан открывать исходники.
  Для платформы, которую вы, возможно, захотите продавать, это **бизнес-решение,
  а не техническое**, и принимать его надо сознательно;
- ⚠️ **бесплатная самостоятельная установка ограничена 12 пользователями на пространство** —
  по отзывам, повторяет ограничение бесплатного облачного тарифа;
- нет настраиваемых полей под свои нужды;
- **нет встроенной связи с репозиториями кода**;
- нет планировщика, критического пути, пула ресурсов — «расширение внутри заранее
  заданной модели управления проектами»;
- **Python на бэкенде** — расходится с вашим TypeScript;
- нет чата между людьми как отдельного продукта (обсуждение живёт в задачах).

## Huly

| | |
|---|---|
| Лицензия | **EPL-2.0** (по отзывам; уточнить у источника) |
| Позиционирование | замена Notion + Slack + Linear в одном |
| Скачано | комплект `huly-selfhost` |

### Что разворачивается — 14 сервисов

Свои восемь:

| Сервис | Роль |
|---|---|
| `front` | веб-приложение и статика |
| `account` | вход, регистрация, токены, членство в пространствах |
| **`transactor`** | ядро: держит веб-сокеты с клиентами, проводит **все** изменения данных, применяет бизнес-правила, публикует события в очередь |
| `workspace` | жизненный цикл пространств, фоновые работы |
| `collaborator` | совместное редактирование на Y.js (CRDT), присутствие |
| `fulltext` | читает события из очереди и поддерживает поисковый индекс |
| `rekoni` | извлекает текст из PDF, DOC, DOCX, RTF, чтобы их можно было искать |
| `stats` | сбор метрик и здоровья |

Чужое: **nginx** · **CockroachDB** (основная база) · **Elasticsearch** (поиск) ·
**MinIO** (файлы) · **Redpanda** (совместимая с Kafka очередь) · **HulyKVS** ·
плюс **MongoDB** в compose. Около **шестнадцати контейнеров**.

Связи: клиент ↔ nginx ↔ сервисы (HTTP и веб-сокеты) · `transactor` → Redpanda →
`fulltext` (асинхронно) · сервисы → CockroachDB напрямую · файлы через S3-совместимый MinIO.

### Плюсы

- **единственный из всех с настоящим набором «чат + задачи + документы + видео»**
  в одном продукте — по составу ближе всего к тому, что описано в вашем бизнес-ТЗ;
- совместное редактирование в реальном времени, встроенные видеовстречи, доски;
- двусторонняя синхронизация с GitHub;
- неограниченное число пользователей и объектов на любом тарифе;
- разделение на `transactor` как единственную точку проведения изменений — архитектурно
  чистое решение: одно место, где применяются правила;
- лицензия EPL-2.0 разрешительная, есть отдельный репозиторий для самостоятельной установки;
- разворачивается примерно за полторы минуты.

### Минусы

- ⚠️ **самый тяжёлый стек из всех.** Пять чужих серверных систем: CockroachDB,
  Elasticsearch, MinIO, Redpanda, MongoDB. По отзывам, «требует умения обслуживать
  MongoDB, Elasticsearch и объектное хранилище под нагрузкой». **Для одного человека
  с агентами это, вероятно, дисквалифицирующий довод** — вспомните закон Люссера
  из вашей же «Стратегии»: каждый последовательный узел умножает ненадёжность вниз;
- жертвует отчётностью и портфелем проектов ради живой совместной работы: «если нужны
  привычные средства управления проектами — вы это перерастёте»;
- молодой проект с быстро меняющейся поверхностью, часть модулей слабее
  специализированных инструментов;
- бэкапы надо покрывать и по базе, и по объектному хранилищу — иначе восстановление
  неполное; перед крупными обновлениями обязательно читать примечания к выпуску;
- **агентов нет вовсе** — их пришлось бы строить с нуля.

## Что это значит для развилки В-1

Три честных наблюдения.

**1. «Plane + докрутить агентов» = построить чужую работу заново.**
Агентская часть — это ровно то, что уже сделано в paperclip, multica и buzz. Начинать
её с нуля поверх plane значит догонять три проекта по 30–80 тысяч звёзд, имея одного
человека, и при этом взять на себя AGPL и ограничение в 12 пользователей.

**2. Huly ближе всех по составу — и дальше всех по стоимости содержания.**
Он единственный даёт «чат + задачи + документы + видео» сразу. Но шестнадцать
контейнеров и пять чужих серверных систем — это не то, что обслуживает один человек,
у которого ещё и продукт не написан. Данность из бизнес-ТЗ («один человек + агенты»)
отсекает его на входе, и это тот случай, когда ограничение работает как фильтр,
а не как жалоба.

**3. Ни один из двух не даёт того, ради чего затевается Amplifie.**
В обоих задача рождается тем, что человек её напечатал. Ваш К1 — «агент слышит
разговор сам» — отсутствует, и в их картине мира ему неоткуда взяться.

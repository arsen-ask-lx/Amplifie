# Buzz — разбор

> Разобран по исходникам 2026-09-04. Локально: `/e/other_project_for_example/buzz`.
> Продукт **не поднимался**, только чтение кода.

**Одной фразой:** самостоятельно размещаемое рабочее пространство, где люди и агенты
сидят в одних комнатах, а каждое действие — подписанное событие в одном общем журнале.

| | |
|---|---|
| Звёзд | ~31 200 |
| Автор | **Block** (компания Джека Дорси), выпущен 21 июля 2026 |
| Язык | Rust (30 крейтов) + TypeScript (настольный клиент) |
| Лицензия | **Apache-2.0** (можно закрытый продукт на его основе) |
| Размер | 29 297 файлов |
| Основа | **Nostr** — журнал подписанных событий, только добавление |

---

## 1. Главная идея: одна форма для человека и агента

Из их README, по смыслу дословно:

> «Это Nostr-реле: каждое сообщение, реакция, шаг рабочего процесса, одобрение ревью и
> событие git — подписанное событие в одном журнале. Одна форма, одна модель личности,
> один аудиторский след — независимо от того, человек автор или процесс.»

У каждого участника — человека и агента — **своя криптографическая пара ключей** (Schnorr).
Агент ограничен **своей личностью**, а не набором флагов разрешений: «так же, как вы
ограничивали бы товарища по команде».

Практическое следствие: агенту не нужен «токен бота». Он подписывает события своим ключом,
и его след неотличим по форме от человеческого, но всегда отличим по авторству.

## 2. Модель данных — не таблицы, а виды событий

Около 80 видов. Ниже — карта по назначению.

**Память агента — отдельное событие.** `KIND_AGENT_ENGRAM` (30174): зашифрованная запись
памяти, адресуемая по `(ключ_агента, вид, d_tag)`, где `d_tag` — HMAC над ключом разговора
«агент↔владелец». То есть память агента приватна для пары «агент — его владелец» и не
читается пространством.

**Кадр наблюдателя** (`KIND_AGENT_OBSERVER_FRAME`, 24200) — эфемерная зашифрованная
телеметрия и управление сессией агента, видимая владельцу. Это наблюдение **за** агентом,
а не наблюдение агентом. Эфемерные события (20000–29999) идут через Redis и **никогда
не сохраняются**.

## 3. Ключевая находка: агент может слушать без упоминания

`crates/buzz-acp/src/filter.rs`. У агента есть **правила подписки**, и это единственный
найденный мной в трёх продуктах механизм, допускающий К1:

```rust
pub struct SubscriptionRule {
    name: String,
    channels: ChannelScope,        // "all" ИЛИ список каналов
    kinds: Vec<u32>,               // пусто = любые
    require_mention: bool,         // ← НЕОБЯЗАТЕЛЕН
    filter: Option<String>,        // булево выражение по событию
    prompt_tag: Option<String>,    // какое правило сработало — уходит в промпт
    compiled_filter: Option<Arc<evalexpr::Node>>,
    consecutive_timeouts: Arc<AtomicU32>,
}
```

Выражение считается над контекстом события: `content` (текст сообщения), `author`,
`kind`, `channel_id`, `timestamp`.

**Инженерия вокруг этого — то, ради чего стоит читать файл:**

| Мера | Значение | Зачем |
|---|---|---|
| предкомпиляция выражения | AST при старте | «`match_event` никогда не разбирает строку на горячем пути» |
| ограничение длины | `MAX_EXPR_LEN = 4096` | защита от тяжёлого выражения |
| жёсткий тайм-аут | `EVAL_TIMEOUT = 100 мс` | считается в отдельном потоке |
| ограничение параллелизма | `MAX_CONCURRENT_FILTER_EVALS = 4` | сам захват разрешения тоже ограничен тайм-аутом |
| счётчик подряд идущих тайм-аутов | правило **отключается** | и это **fail-closed**: `match_event` возвращает `None` |
| порядок правил | первое совпадение выигрывает | предсказуемость |

Это ровно та архитектура, которой требует К1: **дешёвый детерминированный отсев до того,
как позвали модель.** Нельзя гонять модель на каждое сообщение каждого канала — разоришься;
выражение отсеивает за микросекунды, модель включается на остаток.

### Как агент понимает, что обратились именно к нему

```rust
fn event_mentions_agent(event, agent_pubkey_hex) -> bool {
    // тег "p" со ссылкой на ключ агента
}
```

Плюс два уровня отсева до этого: **ворота автора** (`owner ∪ allowlist ∪ siblings` — только
владелец, разрешённый список и «братские» агенты) и **гейт `ignore_self`** — собственные
события агента не запускают его самого.

### Вмешательство в работающего агента

Пока агент выполняет ход, новое событие в канале может послать ему сигнал:
`Steer` (подправить курс) · `Interrupt` (прервать) · `OwnerInterrupt` (прервать, только
владелец — авторство перепроверяется отдельно). Либо `None` — событие ждёт в очереди
и доедет, когда ход завершится.

## 4. Устройство самого агента

Два маленьких бинарника, намеренно:

- **`buzz-agent`** — агент по протоколу ACP: говорит по stdio, зовёт модель, пользуется
  инструментами MCP. До 8 одновременных сессий, каждая со своим контекстом; при
  переполнении контекста сессия **сама сворачивает свою историю** и продолжает.
- **`buzz-dev-mcp`** — сервер MCP: даёт любому агенту оболочку и редактор файлов.
  Эфемерные процессы с убийством группы процессов на каждом пути выхода, ограниченный вывод.

Из их же `VISION_AGENT.md`, и это стоит взять как принцип:

> «Кодовый агент должен быть достаточно мал, чтобы держать его в голове. Если вы не можете
> проследить отказ от симптома до первопричины за минуты — система слишком сложна. <…>
> Мы хотели то, что можно прочитать за вечер и с уверенностью проверить.»

И: **«Нет абстракций, отложенных на будущую гибкость»** — прямая формулировка принципа
«не строить на вырост».

Композиция через протоколы, а не импорты: агент не знает, с каким MCP говорит; MCP не знает,
какой агент его зовёт. Поставщика модели меняют одной переменной окружения.

Отдельно: `git-credential-nostr` и `git-sign-nostr` — коммиты подписываются тем же
ключом Nostr. Личность одна на всё.

## 5. Плюсы и минусы

### Плюсы

- **Единственный из трёх с настоящими каналами между людьми** — это мессенджер по природе,
  а не трекер с приделанной консолью;
- **единственный, где агент может слушать без упоминания** (`require_mention: false`),
  причём с грамотным дешёвым предфильтром;
- **Apache-2.0** — можно закрытый продукт;
- за спиной **Block**, а не одиночка: выше шанс, что проект живёт;
- одна форма события для человека и агента — аудиторский след получается бесплатно,
  по построению, а не отдельной подсистемой;
- личность на ключах: агенту не нужен «токен бота», отзыв доступа = отзыв ключа;
- голос (huddle) уже есть — это ваш В-5;
- память агента зашифрована и приватна для пары «агент — владелец»;
- явная культура минимализма («прочитать за вечер»), редкая для проекта такого размера.

### Минусы

- **Rust** — не ваш язык. Из бизнес-ТЗ у вас TypeScript. Настольный клиент на TS,
  но сервер, реле и агент — Rust целиком;
- ⚠️ **незаконченность, названная в их же архитектурном документе**: ворота одобрения
  числятся известным ограничением; `send_dm` и `set_channel_topic` возвращают
  «не реализовано» вместо работы; у реле **нет боевого ограничителя частоты** — только
  заглушка для тестов;
- **нет задач как сущности.** Есть проекты, процессы, git-issue — но доски задач со
  статусами, исполнителями и приоритетами, как в multica или plane, нет. Для вас это
  зеркальная дыра: у paperclip/multica нет чата, у buzz нет трекера;
- Nostr — не общепринятая основа для корпоративного продукта; выбор редкий, значит мало
  чужого опыта и специалистов;
- ~80 видов событий — своя терминология, которую придётся выучить целиком.

## 6. Что берём себе

| Приём | Зачем нам |
|---|---|
| **Правила подписки с необязательным упоминанием** | это и есть К1 в исполнимом виде |
| **Дешёвое булево выражение до вызова модели** | иначе слушающий агент разорит по деньгам |
| **Тайм-аут 100 мс + отключение правила после серии тайм-аутов, fail-closed** | предфильтр не должен вешать систему |
| **Предкомпиляция выражения при старте** | ничего не разбирается на горячем пути |
| **`prompt_tag` — какое правило сработало** | агент знает, почему его позвали |
| **Гейт `ignore_self`** | агент не реагирует на собственные сообщения |
| **Ворота автора (владелец ∪ список ∪ братья)** | не каждый в канале вправе запускать агента |
| **`Steer` / `Interrupt` в работающего агента** | человек может поправить курс, не дожидаясь конца |
| **Одна форма события для человека и агента** | аудиторский след по построению |
| **Эфемерные события не сохраняются** | присутствие и набор текста не засоряют журнал |
| **Память агента приватна паре «агент↔владелец»** | ответ на «а он читает мою личку?» |
| **«Достаточно мал, чтобы держать в голове»** | принцип, а не приём — прямо в наш харнес |

### Чего НЕ брать

- **Nostr как основу** — платить общей незнакомой моделью за то, что нам нужно в одном
  месте, дорого. Идею «одна подписанная форма события для человека и агента» можно взять
  и на обычной базе;
- модерацию, архивы, самодельные эмодзи, GIF, mesh-compute — это про публичное сообщество,
  а у вас внутрикомандный продукт;
- собственный кодовый агент (`buzz-agent`) — вторая часть, и то не факт.

# Отчёты ревью

Чек ревью, а не слово (task-124). До 27.09 в коммитах стояло «ревью: ocr», а шаг правил
`ocr` не выполнялся и отчёта не было — проверить сказанное было нечем. С коммита,
добавившего этот файл, сторож цикла (`tools/checks/cycle-rule.mjs`, `STRICT_SINCE`)
требует у коммита продукта и поставки отчёт **в этом же коммите**, называющий каждый
его файл. Порядок — скилл `.claude/skills/delegate-review/SKILL.md` (до 27.09 — команда
`.claude/commands/delegate-review.md`); ревьюер — агент `.claude/agents/reviewer.md` (task-126).

Имя — `<дата>-<тема>.md`. Строка коммита:
`ревью: ocr — замечаний N, принято M (dock/reviews/<дата>-<тема>.md)`.

## Образец

```markdown
# Ревью: <что за набор правок> (task-NNN)

Дата: 2026-09-27. Режим `ocr`: workspace. Ревьюер — подагент со свежим контекстом.

## Файлы и правила ocr

- `путь/к/файлу.mjs` — правила: <что выдал `ocr delegate rule` по этому файлу, кратко>
- `путь/к/другому.ts` — правила: …

## Замечания

1. `путь/к/файлу.mjs:42` — высокий — <сценарий отказа> — <исправление> — принято
2. `путь/к/другому.ts:7` — низкий — <сценарий> — <исправление> — отвергнуто: <причина>

Итог: замечаний 2, принято 1.
```

Сторож проверяет форму и состав: отчёт в коммите и называет все файлы. Что ревью делал
подагент после `ocr delegate rule`, а не автор задним числом, сторож коммита проверить
не может — это сверка по записи сессии (task-124, шаг 4); CI записи сессии не видит.

# task-120-описание-api-и-его-арбитр: Описание API из наших схем и арбитр, который бьёт по нему живой стенд

Статус: черновик
Риск: средний
Заведено: 2026-09-27

## За 60 секунд

У бека 51 дверь, и что каждая принимает и отдаёт, знают только zod-схемы в коде. Описания
API (OpenAPI) нет, поэтому гейт AQK `api-contract-has-arbiter` зелёный впустую. Делаем:
описание собирается из тех же схем (`@fastify/swagger`, уже лежит у нас попутной зависимостью),
лежит в репозитории, его свежесть держит гейт; Schemathesis из Docker бьёт каждую дверь
живого стенда странными данными и сверяет ответы с описанием — всеми проверками, а не
«не пятисотка».

## 1. Зачем

Сейчас договор фронта и бека держится общими типами `packages/contract` — это ловит
расхождение на сборке, но не ловит, что сервер на деле отдаёт не то, что обещает: лишний
или пропавший ответ, 500 на странном теле, 200 там, где должен быть отказ. Такие поломки
находит человек в интерфейсе. Владелец 27.09: «библиотеки, которые проверяют эндпоинты,
как бек с фронтом соединён» — ставим.

## 3. Варианты

| Вариант | За | Против |
|---|---|---|
| **`@fastify/swagger` из наших zod-схем + Schemathesis** | схемы уже есть, второго источника правды нет; Schemathesis сверяет живые ответы | Python-инструмент — только из Docker |
| Писать `openapi.yaml` руками | ничего не ставить | второй источник правды — разойдётся в первую же неделю |
| Pact (договор от потребителя) | ловит, что нужно именно фронту | два брокера и тесты на обеих сторонах; у нас фронт и бек в одном репозитории с общими типами — избыточно |
| `spectral` | быстрый | проверяет только оформление файла, на врущем сервере код 0 (замер AQK) |
| `openapi-typescript` / orval для фронта | клиент из описания | общие zod-типы уже дают то же; второй генератор — второй источник |

## 4. Как делаем

1. `@fastify/swagger` регистрируется в `buildApp()` ДО маршрутов — только собирает схемы,
   двери наружу (`/docs`, `/openapi.json`) НЕ заводим: новой двери нет.
2. Скрипт `npm run openapi` строит приложение без прослушивания порта, берёт
   `app.swagger()` и пишет `backend/openapi.json`. Файл в git.
3. Гейт свежести: `npm run openapi:check` — пересобрать во временный файл и сравнить;
   разошлось — красный с подсказкой «npm run openapi». Как `deps-lock`.
4. Двери без схемы ответа получают её в `packages/contract` (где уже живут общие схемы),
   иначе Schemathesis нечем сверять ответы. `stream` (SSE) и `metrics` (текст Prometheus)
   описываются типом содержимого без схемы тела и исключаются из генерации данных.
5. Описание называет отказы, которые дверь правда отдаёт: 401, 404, 422, 429. Без этого
   Schemathesis честно краснеет на каждом 429 (`status_code_conformance`).
6. `make api-fuzz`: Schemathesis из Docker-образа, закреплённого по отпечатку, по живому
   стенду, `--checks all`, печенька сессии заведённого скриптом человека — через `-H`.
   Своё пространство на прогон; фаза `stateful` — по ссылкам из описания, если окупится.
7. Где гоняется: `make api-fuzz` — в CI в задании `stack` рядом с приёмочными и перед
   пушем; не в `make check` (нужен стенд, это минуты).

Расхождения с решениями: нет. Р-006 (протокол) не меняется, Р-022 (проверки по собранному
образу) соблюдается — бьём по стенду из образа.

## 11. Риски

- Схемы ответов раскроют, что бек отдаёт больше полей, чем обещает → сериализатор zod
  начнёт их срезать, фронт может потерять поле. → Приёмочные бека и интерфейса по задетым
  дверям до коммита; схема — по тому, что фронт реально читает.
- Schemathesis найдёт много сразу → разбор по одной, записи в долг; проверку не сужаем.
- Регистрация `@fastify/swagger` в рабочем приложении — лишняя память на старте → замер
  памяти процесса до и после; если заметно — регистрировать только в скрипте генерации.
- Образ Schemathesis ~ сотни МБ → только по отпечатку, в CI кеш не нужен.

## Разбор критика

Агент `plan-critic`, 27.09, свежим контекстом: «годен после правок». Все одиннадцать
замечаний приняты; где правка меняет шаги — она обязательна к исполнению наравне с ними.

1. **Дверей 51, а не 43** — пересчёт по `app.printRoutes()`; П-1 считает по нему. Исправлено выше.
2. **Схема ответа роняет дверь в 500, а не только срезает поля**: `serializerCompiler`
   бросает `ResponseSerializationError` на `Date` вместо строки, `null` в не-nullable,
   лишнем поле-различителе. → Каждая дверь, получившая схему, проходит свои приёмочные
   ДО коммита; это отдельный пункт ревью.
3. **`POST /v1/auth/logout` гасит печеньку прогона** — дальше всё 401. → Исключить из
   генерации данных (`--exclude-path`) и проверять отдельной приёмочной, которая уже есть.
4. **Отказов больше, чем 401/404/422/429**: ещё 403, 409, 502–504 (`failures.ts`), 400 у моста,
   204 у `ask`. → Список отказов строится из таблицы `KNOWN` — одно место правды.
5. **Пороги задушат прогон, а описанный 429 сделает его зелёным впустую** (`INVITE` 20/ч,
   `SEND`/`PIN` 30/мин, `LOGIN` 5/мин; `REGISTER` в CI общий с `npm test`). → Отчёт прогона
   обязан печатать число НЕ-429 ответов на дверь; дверь, где их ноль, — провал прогона,
   а не успех. Фаззер в CI — после приёмочных, на своём адресе/человеке; выбор способа —
   на шаге 5 с замером.
6. **Двери моста** (`Authorization: Bridge`, долгое ожидание 25 с, gzip, без zod-схем тела):
   → исключаются из генерации этой задачей и записываются в долг; добавлять им схему тела
   значит сменить 400 на 422 — это смена поведения, не в границах.
7. **Гейт не видит сужения проверок в `schemathesis.toml`**, и «зелёный впустую» неточно —
   сейчас его держит ветка `tsc`. → Без `schemathesis.toml`: все настройки — флагами в
   `tools/ops/api-fuzz.sh`, где гейт их читает; находка «гейт не видит toml» — в AQK.
8. **`buildApp()` требует `DATABASE_URL` при импорте** — сверка свежести в CI без базы упадёт.
   → Скрипт генерации даёт фиктивное окружение; проверка, что пул не соединяется при сборке.
9. **Схемы тел auth и agents живут в маршрутах, а фронт описывает ответы своими типами** в
   `frontend/src/data/api.ts` — второй источник правды. → Тело и ответ переезжают в
   `packages/contract` вместе, фронт берёт типы оттуда (дверь за дверью, в границах задачи).
   Это расширяет «не трогать: фронт» до замены типов в `api.ts`.
10. **Нет схемы безопасности** — `ignored_auth` не проверит 401. → `apiKey in: cookie`
    (`amplifie_session`) для области `requireSession`.
11. **Красного первым нет** — подсадки `red/` гейта не про наш репозиторий. → Первый красный:
    `openapi:check` на отсутствующем `backend/openapi.json`.

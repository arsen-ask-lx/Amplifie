- образ фронта работает от root;
- базовые образы — плавающие теги (`caddy:2-alpine`, `node:26-bookworm-slim`,

- каждая сборка качает пакеты npm заново.

После:
- заголовки CSP, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, запрет рамок;
- оба образа — от непривилегированного пользователя;
- базовые образы — версия и отпечаток;
- установка без названного образа не поднимается и говорит почему;
- повторная сборка берёт пакеты из кеша.

## 1. Зачем

Аудиторская фирма ставит коробку на свой сервер. Три угрозы, которые снимает задача:

- **Рамка.** Злоумышленник встраивает страницу в свой сайт прозрачной рамкой, и человек
  жмёт «Удалить чат», думая, что жмёт другое. Заголовок `frame-ancestors 'none'`
  запрещает это браузеру.
- **Внедрённый скрипт.** Если где-то пропустим экранирование, CSP `script-src 'self'`
  не даст выполниться чужому скрипту и не даст ему отправить данные на чужой адрес
  (`connect-src 'self'`).
- **Чужая сборка.** Два выпуска одного коммита сегодня дают разные образы: тег `2-alpine`
  сдвигается сам. Клиент не может ответить, какой Caddy у него внутри.

## 4. Как делаем

**Заголовки** (`Caddyfile`, на все ответы):
- `Content-Security-Policy`:
  - `default-src 'self'`;
  - `script-src 'self'`;
  - `style-src 'self' 'unsafe-inline'` — цена названа выше;
  - `img-src 'self' data:`;
  - `connect-src 'self'`;
  - `font-src 'self'`;
  - `object-src 'none'`;
  - `base-uri 'self'`;
  - `form-action 'self'`;
  - `frame-ancestors 'none'`;
- `X-Content-Type-Options: nosniff`;
- `Referrer-Policy: strict-origin-when-cross-origin`;
- `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()`;
- `X-Frame-Options: DENY` — для старых браузеров, дублирует `frame-ancestors`;
- `-Server` — не называть версию сервера.

**HSTS не ставится:** установка пока без TLS (`:80`). Заголовок HSTS по HTTP браузер
игнорирует, а при появлении домена его ставит сам Caddy вместе с сертификатом —
это условие записывается в Д-35, запись закрывается остальным.

**Образ фронта:**
- `# syntax=docker/dockerfile:1`;
- `caddy:2.11.4-alpine@sha256:…`, `node:26.10.0-bookworm-slim@sha256:…`;
- пользователь `amplifie` (uid и gid 10001), `WORKDIR /srv`, `EXPOSE 80`;
- `/data` и `/config` — его;
- `npm ci` с кеш-монтированием.

**Образ бека:** `# syntax`, точная версия и отпечаток `node`, кеш npm.

**Postgres:** `postgres:18.6-alpine@sha256:…` в `compose.yml`.

**Образы без `latest`:**
- `compose.yml` — `${AMPLIFIE_IMAGE_API:?…}` с объяснением, откуда взять строку;
- Makefile — дев-значения `amplifie/api:dev` и `amplifie/web:dev`;
- `make-env.mjs box` пишет имена образов с версией выпуска;
- `check-delivery.sh` собирает под этими именами и поднимает установку без переменных
  окружения make — только из `.env` поставки.

**Том стенда:** владелец меняется один раз разовым `docker run … chown` (данные не трогаются).
Клиентских установок ещё нет: у них том рождается с верным владельцем.

**Порядок обновления версий** — комментарием у каждого закрепления: правка тега и
отпечатка одной строкой, затем `make delivery`.

Расхождения с решениями: нет. Р-030 («собрано один раз, запускается везде») получает
то, чего ему не хватало.

## 11. Риски

- **CSP ломает то, что сценарии не проходят** — сквозной путь плюс полный набор;
  регресс ловится консолью. `'unsafe-inline'` у стилей — названная цена.
- **Старый том стенда root** — разовая смена владельца; клиентских томов нет.
- **Отпечатки устаревают — уязвимости не обновляются сами** → обновление — правкой строки
  и `make delivery`; напоминание — в Д-36 порогом «раз в выпуск».

## Вторая редакция — что изменилось после разбора

Переписано по разбору критика; §4 выше — первая редакция, действует это:

- **Версия выпуска — строкой в `compose.yml` поставки**, а не в `.env`: сборка выпуска
  (`check-delivery.sh`) подставляет `amplifie/api:<версия>` вместо `${AMPLIFIE_IMAGE_API:?…}`.
  `.env` клиента не перезаписывается — версия в нём молча держала бы старые образы.
  `make-env.mjs` не меняется.
- **Стенд** получает имена образов из Makefile (`?=` `amplifie/*:dev`), конвейер — из
  `env` уровня всего `ci.yml`.
- **Postgres** — точный тег `18.6-alpine` без отпечатка: отпечаток в compose не переживает
  `docker load` на классическом хранилище. Отпечатки — только в `FROM` (через `ARG`).
- **Строки `# syntax=` нет**: плавающий тег и поход в реестр; кеш-монтирования работают без неё.
- **Права:** у всех наших контейнеров `cap_drop: [ALL]` и `no-new-privileges`; у Caddy
  возвращён только `NET_BIND_SERVICE` (без него бинарник с файловым правом не запускается).
- **CSP:** `font-src 'self' data:` (Vite вшил woff2 расширенной кириллицы), `img-src 'self'`;
  `Referrer-Policy: same-origin` — адрес закрытого контура не уходит по ссылкам;
  COOP и CORP `same-origin`.
- **Кеш статики:** страница `no-cache`, `/assets/*` — на год, отсутствующий файл сборки — 404
  (прежде HTML вместо скрипта — белый экран после обновления).
- **Сторож CSP во всех интерфейсных сценариях** (`frontend/tests/ui/guard.ts`): запись
  браузера о нарушении роняет любой сценарий.
- **Старый том Caddy** — `make caddy-volume`: Caddy со старым томом работает, но пишет
  «permission denied» и не сможет записать сертификат; отказа при старте нет.
- **HSTS** — строкой `Strict-Transport-Security` в блоке с доменом; Caddy сам её не ставит.

- 10. **П-4 не ловит невидимые нарушения** — принято: общий сторож `guard.ts`.

- 13. **`# syntax` — плавающий тег** — принято: строки нет.
- 14. **Нет заголовков кеша** — принято, с 404 на отсутствующий файл сборки.

## 3. Как делаем

1. **Роли — тонкие агенты.** `delegate-review` сейчас — команда
   (`.claude/commands/delegate-review.md`), а поле `skills:` подгружает только скиллы.
   Поэтому команда **переезжает** в `.claude/skills/delegate-review/SKILL.md` (`git mv`,
   одна копия; скилл вызывается тем же `/delegate-review` — документация скиллов: команды
   слиты со скиллами). Затем `.claude/agents/reviewer.md` (`model: sonnet`, только чтение
   и Bash, `skills: [delegate-review, test-quality]`), `researcher.md` (`model: sonnet`,
   чтение и веб, `skills: [research-before-build]`), `plan-critic.md` — `model: opus`,
   `skills: [plan-quality]`. Текст знания в агента не копируется.
2. **Таблица «этап → роль → модель»** — короткий раздел в `AGENTS.md` со ссылкой на
   справочник; скилл `delegate-review` называет агента `reviewer` и когда звать Opus.
   Сторож ревью (`isReviewer` в `tools/agent/trace-rules.mjs`) засчитывает только
   `subagent_type: "reviewer"` — как `isCritic` для критика; иначе новое поведение не
   отличить от старого (разбор критика).
3. **Сторож «CI красный — сначала разбор» — на коммите, а не на каждой правке.** Хук
   `commit-msg` (рядом с `review-audit`): последний законченный прогон CI ветки красный —
   берём имена упавших работ и тестов из `gh`; каждое упавшее есть в
   `tools/ratchets/ci-known-red.txt` со ссылкой на Д-NN — пропускаем; иначе коммит
   отклоняется до файла разбора `dock/ci/<прогон>.md` с четырьмя разделами (текст падения,
   класс, причина, что уже описано). Коммит редок и последователен — ни кеша, ни гонки
   параллельных агентов. Нет `gh` или сети — пропуск с предупреждением (fail-open назван
   вслух: иначе без сети нельзя закоммитить ничего).
4. **Скиллы:** `k6-load-testing` под наши `tools/load/k6/*.js` и `make k6*`;
   `security-review` — только раздел «fail-open» с примерами Fastify/Node.

Отвергнуто: agent teams (экспериментально, дороже подагентов, не для последовательной
работы — документация Claude Code); всё скиллами (теряем контекст и модель);
восьмиступенчатый конвейер `audit_project` (масштаб не наш).

Расхождения с решениями: нет. Новых зависимостей нет (`gh` уже стоит).

## 4. Шаги

1. Команда `delegate-review` → скилл (`git mv`); агенты `reviewer`, `researcher`, модель и
   скиллы у `plan-critic`; раздел в `AGENTS.md`; `isReviewer` требует агента `reviewer` —
   файлы: `.claude/commands/delegate-review.md` → `.claude/skills/delegate-review/SKILL.md`,
   `.claude/agents/*.md`, `AGENTS.md`, `tools/agent/trace-rules.mjs` и его тест;
   проверка: подсадка «ревью произвольным агентом» → красное, «агентом reviewer» → зелёное;
   `entry-docs-agree`, `make docs`, `trace-check`; ревью коммита агентом `reviewer`
   проходит `review-audit`.
2. Сторож CI: чистое правило (упавшее ⊆ известных; разбор с четырьмя разделами) с
   подсадками, проверка в `commit-msg`, храповик известных красных — файлы:
   `tools/agent/ci-red-rules.mjs` и тест, `tools/agent/ci-red-audit.mjs`,
   `.githooks/commit-msg`, `tools/ratchets/ci-known-red.txt`, `dock/ci/README.md`,
   `Makefile`, `package.json`, `.aqk.yml`, `tools/ratchets/gates-declared.txt`;
   проверка: подсадки красное/зелёное, живой прогон на текущем CI ветки.
3. Скиллы `k6-load-testing`, `security-review` — файлы: `.claude/skills/*/SKILL.md`,
   `AGENTS.md` («задача → скилл»); проверка: `make docs`.
4. Карта, журнал — файлы: `dock/README.md`, этот план.

## 5. Признаки приёмки

- П-1: ревью произвольным подагентом со словом «ревью» → `review-audit` красный; агентом
  `reviewer` (в записи сессии `subagent_type: "reviewer"`, модель Sonnet) → зелёный.
- П-2: CI красный на неизвестном падении → коммит отклонён с подсказкой; после файла
  разбора — проходит; красный только на известных из храповика → проходит.
- П-3: `gh` недоступен → коммит проходит с предупреждением.
- П-4: `make check` зелёный.

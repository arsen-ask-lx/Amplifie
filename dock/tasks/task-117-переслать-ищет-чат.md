## За 60 секунд

записано у `api.conversations`: «дверь получит `?q=&limit=` и станет отвечать „найди чат“,

Сейчас «Переслать» просит у сервера все чаты пространства одним ответом: на засеянной базе
это 1,4 МБ и 5 241 строка. Поля поиска в окне нет, отказ загрузки молча проглатывается.

После:
- в окне есть поле поиска;
- пустое поле показывает чаты, уже известные панели, — без запроса к серверу;
- набор ищет **отдельной дверью** `POST /v1/search/chats`: текст запроса едет в теле,
  не в адресе, — так устроен и поиск по сообщениям;
- старая дверь `GET /v1/conversations` отдаёт не больше ста строк;
- отказ виден строкой с «Повторить».

**Отступление от формы из решения владельца.** Решение говорило «`?q=` в адресе».
Договор (`packages/contract/src/api.ts`, `searchBody`) запрещает текст поиска в адресе:
адрес пишется в журналы сервера и прокси, а названия приватных чатов — тоже переписка
людей. Суть решения («найди чат, а не отдай всё») выполняется целиком. Изменилась только
форма: адрес — ради закрытой записи журналов, а предел остаётся на старой двери.

## 1. Зачем

Человек нажал «Переслать» в пространстве с тысячами чатов.

Сейчас:
- вкладка тянет весь список;
- окно показывает простыню, чат находится только листанием;
- если ответ не пришёл, остаются чаты панели, и человек не знает, что остальных не видно.

После:
- окно сразу показывает чаты панели;
- набор букв ищет по всем видимым чатам, включая свёрнутые папки;
- Enter пересылает только в чат из выдачи, которая соответствует набранному;
- отказ назван строкой в окне.

## 4. Как делаем

### Сервер

- **Договор:** `chatSearchBody` — `q` от 1 до 100 знаков после обрезки краёв, `limit` —
  целое 1–50 (по умолчанию 20). Ответ — `chatsFound`: `{ items: Conversation[] }`.
- **Дверь** `POST /v1/search/chats`, порог `SEARCH`.
  - Только корневые чаты, которые человек видит.
  - Совпадение без учёта регистра и `ё`/`е` — `replace(lower(title), 'ё', 'е') LIKE %q%`;
    знаки `%`, `_`, `\` в `q` экранируются.
  - Порядок: сначала названия, начинающиеся с запроса, затем по названию. Папки
    (`listProjectsFor`) не запрашиваются.
- **Старая дверь** `GET /v1/conversations?limit=` — 1–100, по умолчанию 100; мусор —
  по умолчанию, как у `pageSize`. Порядок и форма прежние, в спеке это «первые сто».

**Цена — замер на засеянной базе** (5 241 корневой чат, `EXPLAIN (ANALYZE, BUFFERS)`,
два прогона, числа совпали):

| запрос | блоков | время |
|---|---|---|
| «а» (подходят все) | 16 126 | 13,7–14,3 мс |
| «чат 38» | 429 | 4,2–4,5 мс |
| нет совпадений | 118 | — |

Подсчёты свежести и непрочитанного отложены до найденных 20 строк (`loops=20`).
Остаток — проверка видимости у каждого подходящего чата. **Порог:** пространство больше
20 000 чатов (ожидаемо ~60 тыс. блоков на одну букву). Тогда — вариант В и триграммный
индекс, отдельным планом.

### Окно

- **Общий хук `usePausedAsk`** — вынесен из `useSearch` без изменения поведения поиска
  по сообщениям: пауза 400 мс, отмена, память по ключу, «Повторить». Выдача помнит ключ,
  к которому относится.
- **`ForwardPicker`:**
  - `CommandField` сверху;
  - пустое поле — корневые чаты панели;
  - набор: пока ищем — чаты панели, отфильтрованные по набранному на месте; найдено —
    выдача сервера;
  - стрелки выбирают; Enter пересылает в выбранный из показанного списка, а показанный
    список всегда соответствует набранному;
  - отказ — строка «Не удалось найти чаты» и «Повторить»; пусто — «Ничего не нашлось»;
  - `role="dialog"`, `aria-label`, `listbox`/`option`, как у `SearchDialog`;
  - после закрытия — `focusField()`: курсор возвращается в поле ввода чата.
  - Ловушки Tab нет — так же, как у `SearchDialog`: свой слой без блокировки фона.
    Перевод обоих окон на `Dialog` набора — отдельная запись в очереди, не здесь.

Расхождения с решениями: да — форма из решения владельца 16.09 (`?q=` в адресе) заменена
отдельной дверью с текстом в теле. Причина — запрет договора (task-100); суть решения
сохранена.

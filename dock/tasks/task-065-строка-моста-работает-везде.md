## 1. Зачем

Владелец взял на сайте строку подключения и запустил её в cmd, PowerShell и WSL — все три
ответили «нет package.json». Строка `npm run bridge -- --code <код>` — скрипт нашего
репозитория и работает только из папки с кодом; адреса сервера в ней нет, и мост идёт на
`localhost:8477`. Коллега на другой машине не подключится вовсе.

После задачи строка с сайта одна и та же для cmd, PowerShell, bash и zsh — Windows, WSL,
Mac, Linux — и запускается из любой папки: нужен только Node. Это запасной путь
программистов по [Р-036](../decisions/036-как-мост-попадает-к-человеку.md); программа
для всех — следующим планом.

## 2. Что уже есть

- `bridge/src/main.ts`, `bridge/src/settings.ts` — мост; из чужого берёт только `@amplifie/model`,
  остальное — встроенные модули Node;
- `backend/src/surface/http/routes/bridge.ts` — выдаёт код и собирает строку `command`;
- `backend/Dockerfile` — образ бека, в нём моста нет;
- Caddy проводит `/v1/*` к беку — отдельной двери наружу не нужно;
- `esbuild` уже лежит в дереве (через Vite), `npx` умеет ставить пакет по ссылке на архив —
  проверено 11.09 пробным пакетом из домашней папки.

## 3. Как делаем

Мост собирается в один файл (`esbuild`) и упаковывается в npm-архив при сборке образа бека.
Бек раздаёт архив по адресу с отпечатком содержимого — `npx` кеширует по адресу, и новый
мост получает новый адрес, а не старый из кеша. Строку собирает сервер из заголовка
`Origin` запроса (браузер шлёт его сам), поэтому адрес в строке — ровно тот, с которого
человек открыл сайт:

```
npx --yes <адрес>/v1/bridge/package/amplifie-bridge-<отпечаток>.tgz --url <адрес> --code <код>
```

Не npm-реестр: он требует аккаунта и публикации наружу (Р-036). Фронт не меняется:
`ModelScreen.tsx` в работе у владельца (task-062), а строку он и так берёт с сервера.

**Расхождения с принятыми решениями:** расхождений нет — исполняет пункт «А» из Р-036.

## 4. Шаги

1. Красный приёмочный: строка несёт адрес и `npx`, архив скачивается, чужое имя — 404.
   - файлы: `backend/tests/bridge.e2e.test.ts`
2. Сборка архива: `bridge/pack.mjs`, скрипт `bridge:pack`, `esbuild` явной зависимостью.
   - файлы: `bridge/pack.mjs`, `package.json`, `package-lock.json`
3. Образ бека везёт архив; бек раздаёт его и собирает строку.
   - файлы: `backend/Dockerfile`, `backend/src/surface/http/routes/bridge.ts`
4. Подсказка моста без кода говорит «возьмите строку на сайте», а не `npm run bridge`.
   - файлы: `bridge/src/main.ts`
5. Живой прогон строкой с сайта: cmd, PowerShell, Git Bash, WSL.

## 5. Признаки приёмки

- П-1: строка с сайта подключает мост из домашней папки в cmd, PowerShell, Git Bash и WSL.
- П-2: в строке адрес того сайта, с которого её взяли.
- П-3: новый мост — новый адрес архива.

## 6. Вопросы к тестам

- В-1: строка — `npx` по адресу архива, `--url` равен `Origin`, код на месте (приёмочный);
- В-2: архив по адресу из строки отдаётся и это gzip; чужое имя — 404 (приёмочный).

**Бюджет:** 2 приёмочных + живой прогон в четырёх оболочках.

## 7. Границы

- менять: файлы из шагов;
- не трогать: `ModelScreen.tsx` (task-062 владельца), протокол моста, выдачу кода;
- Mac проверить не на чем — там тот же `npx` и zsh; это вывод, а не проверка.

## 8. Арбитр

Приёмочные В-1, В-2 против стенда; живой прогон П-1 строкой, скопированной с сайта.

## 9. Наблюдаемость

Не требуется: подключение моста уже видно на сайте («на связи») и в журнале выдачи кода.

## 10. Риски

- сервер раздаёт исполняемый код: архив собирается из нашего же исходника при сборке
  образа, адрес — наш же сайт, заголовок `Origin` подменить может только сам
  запускающий, и навредит он только себе;
- у человека нет Node — строка не сработает; это путь программистов, для остальных —
  программа (Р-036).

### Неожиданности

- **Мост в живом прогоне переписал бы настоящий `~/.amplifie/bridge.json` владельца** —
  тестовые запуски шли с подменённой домашней папкой.
- **`esbuild` сначала лёг в корень** — сторож мёртвого кода не видит там его потребителя;
  перенесён в зависимости моста.
- Node у человека нужен от 20-го: мост собран под него, а не под наш 24-й.
- **Владелец запустил строку — и мост пропустил код** (11.09, после сдачи): сохранённое
  подключение к тому же адресу побеждало код из строки, а старый ключ сервер не признавал —
  мост стучался вечно. Мои четыре прогона шли с чистой домашней папкой и этого не видели.
  Теперь код в строке важнее сохранённого, а непризнанный мост останавливается с подсказкой;
  оба случая проверены живьём на папке со старым подключением.

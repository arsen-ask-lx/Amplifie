## 1. Зачем

Владелец хочет, чтобы Amplifie использовал свежий Agent Quality Kit и получил
честный отчёт о текущем состоянии репозитория. Сейчас локальный `make` и CI
запускают `0.12.0`, а npm публикует `0.14.0`.

## 2. Что уже есть

- `Makefile` запускает `doctor` и `doctor --run` через закреплённую версию;
- `.github/workflows/ci.yml` запускает тот же арбитр;
- `.aqk.yml` — манифест гейтов Amplifie;
- task-029 закрепил предыдущий выпуск `0.12.0`.

## 3. Как делаем

Сверяем релиз с npm и официальными тегами, меняем три закрепления `0.12.0`
на `0.14.0`, затем запускаем штатный `make aqk` и `make check`. Команды AQK,
которые могут менять дерево (`init`, `start`, `add`, `badge`, `context --install`),
не запускаем.

**Расхождения с принятыми решениями:** расхождений нет: меняется версия
арбитра, продуктовое поведение не меняется.

## 4. Шаги

1. Сверить `latest` в npm и официальный тег.
   - файлы: только чтение;
   - проверка: оба источника называют `0.14.0`.
2. Обновить закрепления в локальном прогоне и CI.
   - файлы: `Makefile`, `.github/workflows/ci.yml`;
   - проверка: поиск не находит `agent-quality-kit@0.12.0` вне исторических записей.
3. Прочитать документацию `0.14.0` по `doctor`, `doctor --run`, `context`,
   `report`, `probe` и отличить read-only команды от пишущих.
   - файлы: только чтение;
   - проверка: в итоговом отчёте названы использованные команды и границы.
4. Прогнать новый арбитр по всему репозиторию.
   - файлы: штатный игнорируемый `.aqk/last-run.md` допустим;
   - проверка: `make aqk`, `make check`; каждый красный или совещательный исход назван.

## 5. Признаки приёмки

- П-1: локальная команда и CI используют ровно `0.14.0`;
- П-2: новый `doctor` читает текущий `.aqk.yml` без автоматической миграции;
- П-3: отчёт отделяет дефекты проекта от недоступного стенда и совещательных гейтов.

## 6. Вопросы к тестам

- В-1: «оба места закрепления совпадают?»
  - почему важно: локальная проверка и CI не должны судить разными арбитрами;
  - как проверим: поиск по двум файлам;
  - тестов: 0 — это статическая сверка закреплений.
- В-2: «объявленные гейты запускаются новым AQK?»
  - почему важно: обновление не должно отключить проверки молча;
  - как проверим: `make check`;
  - тестов: 0 — сам прогон является арбитром.

**Бюджет:** три строки закрепления и запись результата; продуктовый код не меняется.

## 7. Границы

- читать: npm metadata, официальный репозиторий, README `0.14.0`, `.aqk.yml`;
- менять: `Makefile`, `.github/workflows/ci.yml`, эту задачу, `dock/README.md`;
- создать: не требуется;
- не трогать: продуктовый код, тесты, правила, гейты и чужие незакоммиченные файлы;
- тесты: только через `make`.

## 8. Арбитр

- сверка источников: npm latest и тег `v0.14.0`;
- прогон: `make aqk`, затем `make check`;
- итог: поиск закреплений и `git diff` только ожидаемых файлов.

## 9. Наблюдаемость

Не требуется: внешней функции продукта, хранилища и денег задача не касается.
Коды выхода AQK и каждого упавшего гейта остаются в выводе команд.

## 10. Риски

Новый выпуск меняет понимание манифеста → не применять предложенные миграции
автоматически; остановиться и назвать развилку. Сетевой или npm-кэшовый отказ
→ отделить от дефекта репозитория и повторить с доступом к кэшу.

## За 60 секунд

- **Сейчас.** Выкладка — 10–25 секунд без ответа сервера (замер task-093).
  Отказ в эти секунды ломает экран до перезагрузки страницы:
  1. обновил страницу — **экран входа**, хотя сеанс жив;
  2. открыл чат — **«Не удалось загрузить сообщения» навсегда**, даже если
     лента пришла, а отказал догон сразу после неё;
  3. первая загрузка панели — **«Не удалось загрузить список каналов» навсегда**;
  4. завёл проект, а панель после этого не перечиталась — **форма пишет
     ошибку, хотя проект создан**; второе нажатие заведёт второй;
  5. не перечиталась раскрытая папка — **её чаты пропадают**;
  6. «Показать ещё» — отказ улетает в никуда;
  7. одна строка беды на всё: **строка живых обновлений стирает ошибку
     ленты**, а потом гаснет — пустой чат без объяснения.
- **После.** Четыре загрузки, без которых экрана нет (кто я, панель, первая
  страница ленты, закреплённое), сами повторяются до 30 секунд — дольше
  типичной выкладки. Не вышло — понятная строка и «Повторить». Удачная
  запись не выглядит неудачей. Папка при сбое показывает прежние чаты.
  У ошибок загрузки и у беды живых обновлений — свои строки.
- **Почему так.** Повтор — только там, где без него ломается экран, и у
  каждого вида запроса один хозяин: поток — `liveStream`, догон — `retrying`,
  четыре загрузки — один модуль по сроку. Общий повтор всех чтений
  (вторая редакция) отвергнут: он умножал запросы — опросы настроек,
  порции панели, листание по цитате.
- **Не делаем:** сброс нагрузки (отложен, task-094); повтор записей — без
  ключа повтора он задвоил бы проект; повтор отметки «прочитано» (task-097);
  автоматическую перезагрузку ленты при возвращении потока.
- **Как показать без кода:** остановить `api` на 10 с и открыть страницу
  в это время — экран подождёт и соберётся сам; остановить на минуту —
  появится «Повторить», одно нажатие после подъёма соберёт экран.

## 3. Как делаем

**Модуль `patient.ts` — повтор по сроку.** `patient(attempt, deps)`: повторяет,
пока не прошло 30 с с первой попытки; пауза — `nextDelay` без пола;
у каждой попытки свой предел 10 с (иначе зависший ответ съел бы весь срок).
Повторяются только «сервер недоступен»: не дошли, истёк предел попытки,
ответ 5xx. Остальное (401, 404, 422, 429) отдаётся сразу. Отмена снаружи
(`AbortSignal`) прекращает повторы. Часы, случайность и ожидание приходят
снаружи.

**Кто терпит — явным списком в `api.ts`.** `me`, `panel`, `messages` без
`before`, `pinned`. Остальные чтения — как сейчас. `messages` и `pinned`
принимают `signal`: переход в другой чат отменяет повторы прежнего.

**Смысл отказа — в `trouble.ts`.** `screenTroubleOf(error)`: «сессии-нет» ·
«сервер-недоступен» (5xx, сеть, истёк предел) · «иное». Кнопка «Повторить»
показывается только при «сервер-недоступен».

**Вход.** «Сессии нет» и «иное» (в том числе 429 за общим адресом) —
экран входа, как сейчас. «Сервер недоступен» после 30 с — «Не удаётся
связаться с сервером» и «Повторить».

**Две строки вместо одной.** `chat.failure` — отказы загрузок:
`{ text, retry? }`. `chat.trouble` — беда живых обновлений (`TROUBLE`),
отдельной строкой. `ChatScreen` показывает обе. Строка загрузки гаснет
в начале каждой новой загрузки ленты, а не только в `select`.

**Лента.** Первая страница — через `patient`. Догон уходит из загрузки:
после `feedReady = true` лента зовёт `kick` из `useLiveUpdates` (не `now`:
переход во время сбоя не должен обходить паузу догона). «Нет такого» —
как сейчас; «сервер недоступен» — строка с «Повторить»; «иное» — строка
без кнопки. «Более раннее» и переход по цитате — без повтора, при отказе
строка с «Повторить».

**Первая панель** — через `patient`; не вышло — строка с «Повторить».

**Записи панели.** Запись ждёт только саму запись: окно закрывается,
как только сервер записал. Перечитывание после — без ожидания, отказ
назван осознанным: следующее перечитывание придёт по звонку, переходу или
возврату во вкладку. `openNew` уходит в новый чат сразу; `removeChannel`
выбирает, куда уйти, из загруженного списка без удалённого.

**Порции папок.** «Нет такой» (404) — папка выпадает; любой другой отказ —
у папки остаются прежние чаты, остальная панель применяется.

**«Показать ещё», «Недавние».** Отказ не отклоняет вызов: кнопка на месте.

**Отвергнуто:**
- повтор всех `GET` в слое сети — умножение запросов (опросы, порции,
  листание); у записей и опросов свои хозяева;
- срок по числу попыток — полный разброс даёт в среднем половину обещанного;
- пол `Retry-After` в `patient` — сервер ставит его только на 429, а 429
  здесь не повторяется;
- повтор 429 на «кто я» — за общим адресом это петля без выхода;
- «папка при сбое пробрасывает отказ» — одна больная папка замораживает
  всю панель;
- TanStack Query — новая зависимость ради одного правила; главный наш риск
  (догон, курсор, раздача) не закрывает.

**Размер.** `useChat.ts` (692) и `useRooms.ts` (521) уже больше 500 строк
из `AGENTS.md` (машинный гейт — 800). После task-097 оба становятся меньше;
этот план возвращает не больше 15 строк на файл. Разрез `useChat` — порог
Д-10, не здесь.

## 9. Наблюдаемость

- исход для человека: сбой сервера — пауза, а не поломка;
- отказы: 401/429/4xx — вход или строка без кнопки; 5xx и сеть — повтор
  до 30 с, затем строка с «Повторить»;
- события: всплеск повторов виден в `/metrics` по дверям `me`, `panel`,
  `messages`, `pinned`;
- повтор: только четыре загрузки; записи, опросы и порции — нет.

## 10. Риски

- **пустой экран до 30 с при открытии страницы во время выкладки** →
  честная цена; дольше — строка с кнопкой;
- **перечитывание панели после записи не удалось, а следующего повода нет** →
  строка появится при переходе, возврате во вкладку или звонке; окно
  закрылось без ошибки, поэтому повторного заведения по ошибке не будет;
- **4 загрузки × 6 попыток на вкладку в волне** → окно растёт, разброс
  полный; сброс нагрузки отложен вместе с условием;
- **«Повторить» не нажмут** → строка говорит, что случилось и что сделать.

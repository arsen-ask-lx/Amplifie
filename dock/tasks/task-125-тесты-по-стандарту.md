## 4. Как делаем

1. **Стандарт — скиллом** `.claude/skills/test-quality/SKILL.md`; AGENTS.md — указатель
   «тест — `test-quality`» в «Задача → скилл» и строка в «Тестах». У каждого правила — кто
   держит: **[М]** машина (есть сторож), **[Р]** ревью (сторожа нет — названо честно):
   - назови поломку: какое изменение продукта красит тест [Р];
   - ожидание — литерал, не результат проверяемого кода и его констант [Р];
   - никаких «не пусто» последней проверкой значения [М — `check-weak-asserts`];
   - в браузере — ждать признак, а не время [М — `noPlaywrightWaitForTimeout`];
   - отрицание — с положительным контролем в том же тесте [Р];
   - CSS и пиксели — только где без них не прочитать и не нажать [Р];
   - «кто не должен видеть» — коллега того же пространства, а не только чужой [Р];
   - помощники стенда — из `stand.ts` [Р; копии чистятся в шаге 4];
   - удаление теста — строкой `удалён тест: … — почему` в коммите, по разрешению владельца
     [Р; машинная проверка удалённого `it(` — в долг].
2. **Сторож «не пусто»** — `tools/checks/check-weak-asserts.mjs` (чистое правило + тест с
   подсадками): `toBeTruthy()`, `toBeDefined()`, `not.toBeNull()`, `toBeFalsy()`,
   `not.toBeUndefined()`, `not.toBe(null|undefined)`, `not.toHaveLength(0)` на значении, у
   которого в том же тесте нет точной проверки (белый список матчеров, без `not.`). База —
   **поимённый список** `файл | вызов` в `tools/ratchets/weak-asserts.txt`, одинаковые
   вызовы — с количеством; новое — красное. Предел назван: `assert.ok` из `node:test` не
   ловится (в оснастке это обычно условие).
   Подключение: скрипт в `package.json`, цель в `Makefile`, запись в `.aqk.yml`, пара строк
   в `tools/ratchets/gates-declared.txt`; `.aqk.yml` и `Makefile` — охрана охраны, коммит с
   отчётом ревью.
3. **`noPlaywrightWaitForTimeout`** — после чистки 11 снов, уровнем `error` в `overrides` для
   `frontend/tests/**`; подсадка — тест, который зовёт `biome lint --only=…` на образце во
   временной папке и ждёт отказа (образец в дереве вечно был бы красным). Версию Biome
   закрепить точно, схему выровнять до `2.5.14`. `useExpect`, `noMisplacedAssertion`,
   `noConditionalExpect` — **не включаются**: без настроек дают на наших помощниках ложные.
4. **Чистка по зонам** (как в ревизии), зона — коммит: слабые проверки → точное значение
   (строки уходят из храповика); сны → признак; оракул из реализации → литерал; копии
   помощников → `stand.ts`. Кандидаты С и Д — **список владельцу по зоне**, удаляется только
   одобренное. Исключены из чистки до своих задач: тесты `detect.ts` (32, ждут решения Д-85:
   удалить их — значит удалить продуктовый файл) и `choose.test` (цементирует Д-82: сначала
   красный тест и правка `choose.ts` своей задачей).
5. **Дефекты — в долг до кода**: Д-82 (`choose.ts` — неверные имена в подсказке), Д-83
   (подпись языка кода при правке — проверить), Д-84 (`hasMore` на ровной последней
   странице — проверить), Д-85 (`detect.ts` мёртв, `check-model.mjs:24` врёт — решение
   владельцу), Д-86 (`sse.test.mjs` не запускается), Д-87 (удалённый тест без строки в
   коммите — машинной проверки нет). Строка очереди «дыры: коллега того же пространства».
6. Карта видов тестов — числа и отметки по факту.

Расхождения с решениями: нет. Новых зависимостей нет. Зависимость: `biome.json` вне охраны
охраны (Д-81) — правило можно молча выключить коммитом «прочего»; закрывается Д-81.

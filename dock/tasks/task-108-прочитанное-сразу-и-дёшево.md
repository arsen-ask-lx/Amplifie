## За 60 секунд

- **Сейчас (владелец 21.09):** «листаю вниз, и только через секунду уменьшается
  счётчик — в тг как будто в 10 раз быстрее». Причина одна: число на экране
  сдвигается **ответом сервера** (`useReading`, `onSent`), а отметка уходит
  не чаще раза в 3 с. Экран ждёт и окно, и запрос.
- **После:** число убывает в тот же кадр, когда реплика показалась целиком,
  как у Telegram (`readInboxTill` ставит число до запроса), Mattermost, Zulip
  и Element. Серверу отметка уходит как раньше — не чаще раза в 3 с на чат.
- **Почему так:** экран и сервер — два разных вопроса. Экран отвечает
  «что человек увидел» — сразу; сервер — «что сохранить» — пачкой.
- **Чего НЕ делаем (разбор критика):**
  - «сразу при нуле» — в живом чате ноль наступает после каждой реплики,
    и окно в 3 с исчезло бы: до ~4000 отметок в секунду на 400 вкладках;
  - «сразу при прятании вкладки» с `keepalive` — отдельная правка двери API;
    теряется хвост до 3 с чтения, и число честно вернётся при входе;
  - серверную половину — в task-110.
- **Как показать без кода:** открыть «Стройку» (100 непрочитанных) и листать —
  число убывает непрерывно. Во вкладке «Сеть» — `/read` не чаще раза в 3 с.

## 4. Как делаем

Только `useReading.ts`:
1. `seen(seq)` ставит `readUpTo[id] = max(…, seq)` **сразу** и всегда передаёт
   номер `readMarks.seen` — тот сам отсекает `seq <= want/sent` и после отказа
   примет тот же номер снова. Отсечка в хуке остаётся одна: `seq <= readSeq`
   строки панели (сервер уже знает).
2. Отметка «докуда на экране» живёт в ref, а в state — копия для отрисовки:
   ссылка `seen` не меняется, наблюдатель ленты не пересоздаётся.
3. `onSent` больше не трогает `readUpTo` — только отдаёт ответ сервера панели
   (`onRead`), как и сейчас.
4. **Покинутый чат (второй разбор критика).** Хук держит последние реплики
   каждого чата, где человек был; `readLocally` считает по ним то же, что
   по открытому. Сервер подтвердил — `readSeq` строки сдвинулся, реплики
   выпадают из подсчёта сами. При уходе экранная отметка чата ставится
   в очередь заново и уходит сразу: оборванная сетью не теряется.

## 6. Признаки приёмки — чем докажем

- **П-1 сразу:** ответ `/read` придержан на 5 с (`page.route`), и число
  в строке панели становится меньше исходного **не позже чем через 1,5 с**
  после открытия чата. Сегодня — только через 5 с (ждёт ответа): тест красный.
  Чужая причина исключена: ответ физически не пришёл.
- **П-2 отказ не теряет отметку:** все `/read` обрываются, пока человек дочитывает
  до конца; сеть вернулась, лента сдвинута в пределах увиденного — уходит отметка
  ТОГО ЖЕ номера. Проверено подсадкой: наивная отсечка по экранной отметке
  красит тест (22.09).
- **П-2а покинутый чат не загорается:** ответы придержаны, человек ушёл
  в другой чат — число «Сметы» ни разу не выросло (наблюдатель за строкой).
  Проверено подсадкой: без реплик покинутого чата тест красный (22.09).
- **П-3 пачкой, как раньше:** промежуток между соседними `/read` не меньше 2,7 с
  (окно 3 с минус допуск таймеров), номера растут; плюс `requests.spec.ts` —
  «пачка реплик — не пачка отметок». Покрасит: отправка на каждую реплику.
- **П-5:** регрессия зелёная: `read-instant`, `unread-open`, `unread`,
  `mentions`, `jump`, `requests`; `npm run unit`.

Числа до кода: задержка числа на экране сейчас 0–3 с плюс время ответа →
цель < 1,5 с даже при ответе через 5 с; запросов `/read` за 10 с — как было,
не больше 4. SLO строкой: число на экране не ждёт сервера.

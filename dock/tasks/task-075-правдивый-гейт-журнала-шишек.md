# task-075-правдивый-гейт-журнала-шишек: урок с выводом не краснеет

Статус: одобрен владельцем 2026-09-13 («ок да давай исправим»)

## 1. Зачем

`lesson-has-outcome` должен отличать журнал, где каждая шишка заканчивается
выводом, от дневника без решения. Сейчас `make check` красный на шести старых
записях, хотя у них вывод уже есть. Инструмент, который краснеет на правильном,
приучает не верить всем остальным отказам.

## 2. Что уже есть

- `tools/gates/lesson-has-outcome/check.sh` ищет в датированных разделах
  маркеры результата;
- `dock/incidents/README.md` — настоящий журнал;
- `make aqk-prove` доказал ложноположительное срабатывание на зелёном образце;
- `make check` называет шесть ошибочно помеченных разделов.

## 3. Как делаем

Сначала фиксируем ошибку гейта тестом/образцом, затем исправляем распознавание
внутри одного датированного раздела. Исторические уроки не переписываем ради
формата: гейт должен понимать допустимые уже записанные результаты.

**Расхождения с принятыми решениями:** расхождений нет. Правило журнала
сохраняется: у каждого урока обязан быть явный вывод.

## 4. Шаги

1. Воспроизвести ложноположительный результат на зелёном образце и настоящем журнале.
   - файлы: только чтение;
   - проверка: `make aqk-prove`, `make check` красные именно на этом гейте.
2. Прочитать все ошибочно названные разделы и определить общий допустимый маркер.
   - файлы: `dock/incidents/README.md`, `check.sh`;
   - проверка: правило различает маркер вывода и обычное упоминание символа.
3. Сначала добавить красный и зелёный образцы именно для найденного случая.
   - файлы: `tools/gates/lesson-has-outcome/`;
   - проверка: до реализации образец красный, после — зелёный; образец без вывода остаётся красным.
4. Исправить гейт минимально и прогнать его отдельно, затем весь набор.
   - файлы: `tools/gates/lesson-has-outcome/check.sh`;
   - проверка: `make aqk-prove`, `make check`.

## 5. Признаки приёмки

- П-1: существующая запись журнала с допустимым выводом не краснеет;
- П-2: датированная запись без вывода краснеет;
- П-3: `make aqk-prove` доказывает и красный, и зелёный образец;
- П-4: `make check` зелёный либо называет независимую, не связанную с задачей причину.

## 6. Вопросы к тестам

- В-1: «эмодзи/маркер вывода в записи принимается?»
  - почему важно: это и есть ложноположительное срабатывание;
  - как проверим: зелёный образец с настоящей формой вывода;
  - тестов: 1.
- В-2: «просто рассказ без решения не проходит?»
  - почему важно: иначе исправление выключит правило;
  - как проверим: красный образец без маркера;
  - тестов: 1.

**Бюджет:** один гейт и два образца; продуктовый код не меняется.

## 7. Границы

- читать: журнал шишек, гейт, его образцы, вывод `prove`;
- менять: гейт, его образцы, эту задачу, `dock/README.md`;
- создать: только образцы гейта, если их нет;
- не трогать: продуктовый код, историю журналов, AQK-манифест, чужие изменения;
- тесты: только через `make`.

## 8. Арбитр

- `make aqk-prove` — гейт краснеет на красном и молчит на зелёном;
- `make check` — полный прогон проекта;
- `git diff --check` — только целевые файлы без повреждённой разметки.

## 9. Наблюдаемость

Не требуется: гейт не меняет пользовательское поведение, данные или внешние системы.

## 10. Риски

Слишком широкое распознавание маркера → красный образец без вывода остаётся
обязательным; если он позеленеет, остановиться и сузить правило.

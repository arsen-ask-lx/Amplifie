# task-058-раскрытие-проекта-и-hover-заголовка: надёжное появление чатов и узкий hover

Статус: одобрен владельцем 2026-09-11
Риск: низкий — локальная разметка боковой панели, без API и хранилища
Заведено: 2026-09-11

## 1. Зачем

Человек раскрывает проект с чатами: закрытие плавное, но открытие иногда возникает
сразу конечным кадром. Одновременно кнопка нового проекта должна появляться только
при наведении на строку «Проекты», а не при наведении на сам список проектов.

Пример: курсор над проектом «Смета» не показывает `+`; курсор над строкой «Проекты»
показывает `+`. Нажатие на «Смета» мягко раскрывает его чаты, повторное — мягко
сворачивает и затем убирает тело из потока.

## 2. Что уже есть

- `RoomList.tsx` хранит личный выбор свёрнутых проектов в `localStorage`; это
  единственный источник намерения пользователя.
- `ProjectRow.tsx` оставляет тело в DOM до `transitionend` при закрытии, но при
  открытии координирует два React-состояния через `requestAnimationFrame`.
- `SidebarSection.tsx` содержит заголовок и кнопку `+`; её hover-граница должна
  совпадать ровно с заголовком.
- `styles.css` уже содержит правило: появление нового DOM-узла делается CSS-анимацией,
  а исчезновение — переходом.

## 3. Как делаем

В `ProjectRow` заменяем пару флагов и `requestAnimationFrame` на одну локальную фазу
жизненного цикла: `closed`, `opening`, `open`, `closing`. `collapsed` остаётся
источником намерения в `RoomList`; фаза лишь описывает краткое визуальное состояние.
Открытие запускает CSS keyframe при монтировании, закрытие использует CSS transition и
убирает тело по завершении именно свойства высоты. Длительность и easing живут в одном
CSS-компоненте.

В `SidebarSection` hover и focus-within привязываем к интерактивной строке заголовка,
не к `section` и не к списку под ней.

Не выбираем новую библиотеку анимаций: для одной папки это лишняя зависимость. Не
используем `requestAnimationFrame`: он зависит от момента фактической отрисовки и уже
дал наблюдаемую гонку. `@starting-style` не берём: это более новый механизм, а CSS
keyframe одинаково работает в поддерживаемом приложением Chromium.

**Расхождения с принятыми решениями:** нет.

## 4. Шаги

   - файлы: `frontend/tests/ui/projects.spec.ts`
   - проверка: сценарии красные против текущих rAF/широкого hover-правил.
2. Ввести компактную фазу раскрытия в строке проекта и убрать rAF/два флага.
   - файлы: `frontend/src/app/ProjectRow.tsx`
   - проверка: типы; быстрые повторные клики не оставляют чат в неверном состоянии.
3. Добавить единый CSS-вход и CSS-выход с отключением движения по системной настройке.
   - файлы: `frontend/src/styles.css`, `ProjectRow.tsx`
   - проверка: открытие и закрытие имеют одинаковые длительность и easing; reduced-motion мгновенный.
4. Сузить hover-область `+` до строки заголовка.
   - файлы: `frontend/src/app/SidebarSection.tsx`, UI-тест
   - проверка: наведение на проект оставляет `+` скрытым; на заголовок — показывает.
5. Выполнить штатные проверки и живой обход на собранном адресе.
   - проверка: `make typecheck`, `make lint`, `make test-ui`; открыть и закрыть проект
     на `http://localhost:8477` в обычном и reduced-motion режимах.

## 5. Признаки приёмки

- П-1: нажатие на закрытый непустой проект показывает чаты плавно, без резкого первого кадра.
- П-2: нажатие на открытый проект плавно скрывает чаты и после завершения не оставляет пустого места.
- П-3: быстрое открыть → закрыть → открыть заканчивается открытым списком без застрявшего тела.
- П-4: `+` не появляется при наведении на проект или список; появляется при наведении на строку «Проекты».
- П-5: при `prefers-reduced-motion: reduce` движение не запускается.

## 6. Вопросы к тестам

- В-1: «вход анимируется без гонки кадров?»
  - почему важно: старый тест принимал случайно удачный rAF-кадр, а пользователь видел обратное.
  - как проверим: фаза `opening` и объявленная CSS-анимация появляются вместе; финальное открытое
    состояние доступно после завершения.
  - тестов: 1.
- В-2: «плюс не реагирует на соседний список?»
  - почему важно: это точная граница действия, которую видит человек.
  - как проверим: наведение на строку проекта не меняет видимость, наведение на заголовок меняет.
  - тестов: 1.
- В-3: «движение можно отключить?»
  - почему важно: системная настройка доступности важнее декоративной анимации.
  - как проверим: Playwright с `reducedMotion: reduce` видит конечное состояние без класса анимации.
  - тестов: 1.

## 10. Риски

- Событие transitionend придёт от вложенного узла или прозрачности → принимаем только событие
  корневого узла и свойства `grid-template-rows`.
- Быстрые повторные клики оставят старый обработчик закрытия → фаза является единственным
  локальным жизненным циклом, а обработчик проверяет текущую фазу.
- CSS-анимация появится при первом рендере страницы → начальная раскрытая строка начинает в `open`,
  без класса `opening`.

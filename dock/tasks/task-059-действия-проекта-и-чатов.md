# task-059-действия-проекта-и-чатов: настоящая заводка чата и простые действия строки

## 1. Зачем

В боковой панели человеку нужно сразу видеть, что он может сделать, без лишнего
карандаша и универсальных меню там, где достаточно двух действий. Открытие папки
должно начинаться так же плавно, как закрытие, а не зависеть от кадра React.

Пример: в строке проекта после названия стоят `…` и `+`: `…` открывает уже
существующее меню настроек/закрепления/удаления, `+` открывает настоящее окно
«Новый чат в проекте …». У чата внутри проекта вместо `…` видны кнопки булавки
и удаления. У чата вне проекта сохраняется меню, в котором есть перемещение.

## 2. Что уже есть

- `useRooms.addChannel(title, projectId)` и API уже создают чат сразу внутри проекта.
- `Rail` держит существующее окно `NewChatDialog` для общего нового чата.
- `ProjectRow` содержит карандаш и меню; `ChannelRow` содержит общее меню канала.
- `RoomList` знает, какие строки находятся внутри проекта.
- task-058 добавил локальную фазу анимации с keyframe, но она всё ещё сложнее
  нужного и не устраняет необходимость координировать фазу в React.

## 3. Как делаем

Заменяем rAF/фазы на один признак присутствия тела для закрытия. Открытие получает
первое состояние через нативный CSS `@starting-style`, закрытие — тот же CSS transition
и размонтирование по `transitionend`. Это стандартный паттерн для добавленного DOM-узла,
а не ручная координация кадров.

`Rail` расширяет уже существующий вопрос «завести чат» необязательным проектом и
передаёт команду в `RoomList`; `ProjectRow` только вызывает её. У проекта остаются
три точки и реальный плюс, карандаш удаляется. `ChannelRow` сам выбирает набор
действий по принадлежности: внутри проекта — pin/delete, вне проекта — прежнее меню.

**Расхождения с принятыми решениями:** task-041 закреплял отсутствие `+` у проекта.
Владелец прямо изменил решение: теперь `+` допустим, потому что он вызывает уже
реализованное создание чата в проекте, а не обещает пустую возможность.

## 4. Шаги

1. Написать красные UI-сценарии нового порядка действий и создания чата сразу в проекте.
   - файлы: `frontend/tests/ui/projects.spec.ts`
   - проверка: до реализации нет кнопки `Новый чат в проекте…`, карандаш ещё есть.
2. Упростить раскрытие проекта до presence + CSS `@starting-style`.
   - файлы: `ProjectRow.tsx`, `styles.css`, UI-тест
   - проверка: открытие и закрытие используют один transition; нет `requestAnimationFrame`,
     локальной фазы или таймера; reduced-motion мгновенный.
3. Переставить действия проекта: `…`, затем реальный `+`; открыть существующее окно
   создания чата с заранее известным проектом.
   - файлы: `Rail.tsx`, `RoomList.tsx`, `ProjectRow.tsx`, `ChannelAsks.tsx`
   - проверка: созданный чат приходит с `projectId` выбранного проекта и открывается.
4. Для чата внутри проекта заменить меню на отдельные pin/delete; меню внешнего чата не менять.
   - файлы: `ChannelRow.tsx`, UI-тест
   - проверка: pin меняет порядок, delete вызывает существующее подтверждение; у проектного
     чата нет кнопки трёх точек.
5. Запустить штатные проверки и живой браузерный прогон собранного стенда.
   - проверка: `make typecheck`, `make lint`, `make test-ui`; обычное и reduced-motion.

## 5. Признаки приёмки

- П-1: открытие и закрытие непустого проекта одинаково плавны; открытие не использует rAF.
- П-2: после названия проекта находятся `…`, затем кнопка создания чата; карандаша нет.
- П-3: плюс создаёт и открывает чат сразу внутри выбранного проекта.
- П-4: у чата внутри проекта нет `…`, есть работающие pin и delete.
- П-5: у чата вне проекта сохраняется меню с перемещением в проект.

## 6. Вопросы к тестам

- В-1: «новый плюс действительно создаёт чат в правильном проекте?»
  - почему важно: декоративная иконка — обещание без действия.
  - как проверим: API панели возвращает `projectId` созданного чата; чат виден под проектом.
  - тестов: 1.
- В-2: «у строк не потеряны необходимые действия?»
  - почему важно: удаляя универсальное меню, легко молча убрать рабочее действие.
  - как проверим: проектное меню открывает настройки; pin/delete проектного чата выполняются;
    внешнее меню по-прежнему содержит перенос.
  - тестов: 2.
- В-3: «открытие не зависит от случайного кадра?»
  - почему важно: именно это было причиной резкого появления.
  - как проверим: CSS `@starting-style` задан для открытого тела, код не содержит rAF;
    живой прогон проверяет движение глазами.
  - тестов: 1 + живой арбитр.

## 9. Наблюдаемость

## 10. Риски

- Меню внешнего чата исчезнет вместе с проектным → ветка выбирается только по `projectId`.
- Диалог окажется в двух местах → один `NewChatDialog` остаётся в `Rail`; меняется только
  контекст создания.
- Старый Chromium не поддержит `@starting-style` → проверяем версию стенда до сдачи; при
  неподдержке остановимся и согласуем совместимый fallback, а не добавим скрытый rAF.

## За 60 секунд

- **Сейчас:** поиска по сообщениям нет. Поиск чатов по названию и Ctrl+K
  пропали при перестройке (Д-46). Где обсуждали договор — только листать
  глазами.
- **После:** Ctrl+K открывает строку поиска. Набираешь «договор» — через
  полсекунды сообщения из всех чатов, которые тебе видны:
  - чат, автор, дата;
  - строка текста с подсвеченным словом;
  - **новые сверху**, дальше подгрузкой.

  Щелчок открывает сообщение в чате.

  Как совпадает: «договор» находит «договоры» и «договора», «догов» —
  «договор», «елка» — «ёлка». Чужой закрытый чат не находится никогда.
- **Почему так:** встроенный поиск Postgres в отдельной таблице —
  без нового сервера и зависимостей, как у Matrix Synapse.
  - **Таблица — производная.** Её можно стереть и собрать заново
    из сообщений, поэтому ошибка в ней не портит переписку. Её же
    можно заменить другим движком, не трогая остальное.
  - **Порядок держит триггер в базе:** ни новый путь записи в коде,
    ни выкладка, ни сырой засев не оставят сообщение ненайденным.
  - **Цена:** запись в индекс идёт внутри отправки — меряем задержку
    отправки, а не надеемся.
- **Не делаем:**
  - кусок из середины слова («говор» не найдёт «договор») — решение
    владельца 17.09;
  - поиск внутри одного чата со стрелками «3 из 17» и фильтры «от кого»,
    «по дате» — следующая задача;
  - поиск чатов по названию — Д-41;
  - счётчик «всего найдено».
- **Как показать без кода:**
  1. Ctrl+K → «договор» → сообщение годичной давности со словом «договоры»;
  2. щелчок — оно в чате, подсвечено;
  3. коллега вне закрытого чата ищет то же — сообщения у него нет.

## 4. Как делаем

### Данные

Таблица `message_search`:

| Поле | Что |
|---|---|
| `message_id` | ключ; ссылка на сообщение, каскад |
| `workspace_id` | |
| `conversation_id` | |
| `seq` | |
| `doc tsvector` | вектор текста |

**Копии полей сообщения здесь законны.** Пространство, разговор и номер
у реплики не меняются никогда: перенос чата меняет проект разговора,
а не реплику.

Индексы: GIN по `doc`, btree `(workspace_id, seq)`. Окончательный набор —
**по замеру шага 0**.

**`search_text(body)`** — функция SQL: упоминание заменяется подписью.

**Вектор:**
`to_tsvector('russian', t) || to_tsvector('simple', replace(lower(t), 'ё', 'е'))`.

**Триггер:**
- `AFTER INSERT` на `message`;
- `AFTER UPDATE OF body, deleted_at` на `message`: живая реплика
  с непустым телом → строка вставлена или переписана; удалённая →
  строка удалена;
- закрепление и сдвиг номера изменения триггер не будят.

**Миграция `0027`:** функция → таблица → триггер → заполнение старых
реплик одним `INSERT … SELECT` под `LOCK TABLE message IN SHARE MODE`
→ индекс GIN.
- **Зачем замок.** Старый `api` пишет, пока идёт миграция (`compose.yml`).
  Без замка реплика, записанная между снимком заполнения и включением
  триггера, не ищется никогда. На стенде это секунды.
- **Порог:** база больше миллиона реплик до этой миграции — заполнение
  порциями, своим планом.

### Запрос

**Дверь:** `POST /v1/search/messages`, тело `{ q, before?, limit? }`.
**Тело, а не адрес:** адрес пишется в журналы сервера и прокси.

**Слова запроса:**
- только буквы и цифры, от 2 знаков;
- не больше 8 слов, строка до 200 знаков;
- каждое слово → `to_tsquery('simple', 'слово:*') || to_tsquery('russian', 'слово')`
  после `lower` и замены ё на е;
- слова соединяются через «и»;
- стоп-слово даёт пустую русскую часть и ищется началом слова;
- операторов в слове нет по построению, идёт параметром.

**Один запрос на выдачу:**
- `selectMessages` + соединение с `message_search` по `doc @@` и курсору `seq`;
- живая реплика, живой разговор, `canSee`;
- порядок `seq` по убыванию, предел 21;
- к виду добавлено название разговора.

Удалённое между чтениями не пролезет — чтение одно.

**Частое слово** — главная ловушка (разбор, раздел 2). Выбор — числами
шага 0:
- **Ф-1** — запрос как есть;
- **Ф-2** — ступенчатое окно по `seq`: последние 100 000 номеров, не
  набралось — ×10, и так до начала;
- **Ф-3** — RUM (вариант B), отдельный вопрос владельцу.

### Клиент

- **`shared/markup.ts`:**
  - `lineOf(body)` — строка сообщения без разметки: `parseMarkup` + `plain`,
    упоминание с «@»;
  - `marksIn(line, слова)` — куски «подсветить / нет» по началу слова,
    без учёта регистра и ё. Чистые, с точечными проверками;
- **`SearchDialog`** по Ctrl+K:
  - поле, пауза 400 мс, прежний запрос отменяется;
  - первая страница кешируется по строке, пока окно открыто;
  - строка выдачи: чат · автор · дата, строка текста вокруг первого

  - Enter и щелчок — `openAt(чат, номер)`, окно закрывается;

    отказ — строка и «Повторить».

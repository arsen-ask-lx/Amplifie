## 1. Зачем

Владелец хочет использовать свежую версию своего `agent-ui-kit` при разборе
интерфейса Amplifie. Сейчас проект фиксирует диапазон `^0.1.1`, а lock-файл
фактически ставит `0.1.1`; нужно установить последнюю опубликованную версию и
доказать, что Alt+щелчок по элементу всё ещё записывает заметку в ожидаемый файл.

## 2. Что уже есть

- `frontend/vite.config.ts` подключает `agentUiKit` только к dev-серверу и пишет
  в `dock/замечания.md`;
- `frontend/package.json` содержит `agent-ui-kit: ^0.1.1`;
- `package-lock.json` и локальный `node_modules` содержат точную версию `0.1.1`;
- единый пользовательский вход для разработки — `make work` на порту 8477.

## 3. Как делаем

После одобрения сверяем последнюю опубликованную версию по первичному источнику
(npm registry и release/tag исходного репозитория), обновляем только manifest и
lock-файл через существующий `make install`, затем проверяем сборку и живой
сценарий тыкалки. Версию закрепляем согласно фактической политике lock-файла;
новый API не переносим в продуктовый код без отдельной развилки.

**Расхождений с принятыми решениями нет:** пакет остаётся dev-only и не попадает
в production build.

## 4. Шаги

1. Сверить latest, changelog и требования новой версии с npm/GitHub.
   - файлы: только чтение `frontend/package.json`, `package-lock.json`, пакет;
   - проверка: версия и дата подтверждены первичным источником.
2. До обновления зафиксировать красную проверку версии и зелёную базовую сборку.
   - файлы: не менять;
   - проверка: текущий lock не равен подтверждённому latest; `make typecheck`.
3. Обновить зависимость штатным входом проекта.
   - файлы: `frontend/package.json`, `package-lock.json`;
   - проверка: manifest и lock указывают одну подтверждённую версию.
4. Прогнать автоматические и живые проверки.
   - файлы: не менять продуктовый код;
   - проверка: `make check`, `make work`, Alt+щелчок → тестовая заметка.

## 5. Признаки приёмки

- П-1: открыть manifest и lock → в обоих установлена последняя опубликованная
  версия из первичного источника;
- П-2: выполнить `make check` → быстрые проверки проходят либо каждый внешний
  блокер назван отдельно;
- П-3: открыть dev-экран и сделать Alt+щелчок → поле открывается, Enter добавляет
  заметку с маршрутом и компонентом в `dock/замечания.md`;
- П-4: собрать production frontend → клиент тыкалки в артефакт не внедрён.

## 6. Вопросы к тестам

- В-1: «обновление не ломает Vite-конфиг и production build?»
  - почему важно: пакет выполняется внутри сборщика;
  - как проверим: типы, сборка и отсутствие dev-клиента в production;
  - тестов: 2.
- В-2: «основной пользовательский жест действительно записывает заметку?»
  - почему важно: это единственная ценность инструмента в Amplifie;
  - как проверим: живой Alt+щелчок и чтение добавленной записи;
  - тестов: 1 живой сценарий.

**Бюджет:** продуктовых строк нет; два файла зависимости и три проверки.

## 7. Границы

- читать: metadata npm/GitHub, README/changelog пакета, текущий Vite-конфиг;
- менять: `frontend/package.json`, `package-lock.json`, этот план, `dock/README.md`;
- создать: этот план;

## 8. Арбитр

- тест: `make check` и production build внутри него;
- живой прогон: dev-сервер через `make work`, Alt+щелчок и запись заметки;
- сверка с источником: npm registry и официальный репозиторий пакета на дату
  выполнения.

## 9. Наблюдаемость

- проверяемый исход: точная версия в lock-файле и новая заметка из живого UI;
- отказ: код установки/сборки или отсутствие записи фиксируются в логе плана;
- безопасные поля: версия, URL релиза и вывод проверки; токены не нужны;
- повтор: повторная установка той же версии не меняет lock-файл;
- доказательство после работы: команды, diff двух файлов и живой сценарий.

## 10. Риски

- новая major-версия меняет API → остановиться и вынести совместимость на выбор
  владельца, не угадывать адаптацию;
- registry и исходный репозиторий расходятся → ставить только опубликованный npm
  artifact, расхождение записать;
- живой тест добавляет запись → использовать отдельную явно тестовую запись и не
  удалять её без отдельного разрешения владельца.

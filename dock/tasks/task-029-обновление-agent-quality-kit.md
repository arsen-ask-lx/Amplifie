# task-029-обновление-agent-quality-kit: обновить и прогнать AQK

Статус: сделан 11.09 — одобрен словами владельца 11.09 («ты его обнови и пользуйся им и давай фидбек»); версия поднята до 0.12.0, а не 0.10.0: вышла позже плана
Риск: средний
Заведено: 2026-09-09

---

## 1. Зачем

Владелец хочет проверить Amplifie свежим выпуском своего Agent Quality Kit.
Сейчас `Makefile` и CI закрепляют `agent-quality-kit@0.7.0`; npm показывает
последний опубликованный выпуск `0.10.0` от 2026-09-09. Нужно обновить обе точки
одним изменением и прогнать новый `doctor`, его гейты и новые диагностические
команды, не позволяя инструменту молча переписать правила проекта.

## 2. Что уже есть

- `.aqk.yml` объявляет 29 собственных и переносимых гейтов проекта;
- `Makefile` содержит `make aqk`, `make gates`, `make ci-gates` и `make check`;
- `.github/workflows/ci.yml` запускает закреплённый AQK;
- npm и официальный репозиторий указывают на `0.10.0`; выпуск требует Node 18+
  и `sh`, а проект уже использует Node 24 и Git Bash/Unix shell.

## 3. Как делаем

После словесного одобрения сначала фиксируем красную проверку версии: обе точки
ещё равны `0.7.0`, а latest — `0.10.0`. Затем меняем только две ссылки на версию,
прогоняем инструмент через существующие цели `make` и отдельно читаем вывод
новых read-only команд `vitals`, `probe` и `report`, если они не требуют менять
рабочие файлы. Любое предлагаемое AQK изменение правил остаётся предложением:
`init`, `add`, `badge` и другие пишущие команды без отдельного плана не запускаются.

**Расхождение с принятыми решениями:** нет; меняется версия арбитра, а не набор
обещаний проекта. Если новый выпуск меняет смысл уровня или манифеста, работа
останавливается на развилке и требует решения владельца.

## 4. Шаги

1. Сверить `0.10.0`, дату, changelog и команды по npm/GitHub.
   - файлы: только чтение;
   - проверка: два первичных источника совпали.
2. Зафиксировать красный version-check и зелёный/красный исход старого арбитра.
   - файлы: не менять;
   - проверка: `make aqk`, затем сравнение двух закреплённых версий с latest.
3. Обновить закрепление одной версией.
   - файлы: `Makefile`, `.github/workflows/ci.yml`;
   - проверка: поиск не находит `agent-quality-kit@0.7.0`, обе точки равны `0.10.0`.
4. Прогнать новый AQK и проектные арбитры.
   - файлы: не менять, кроме штатных игнорируемых отчётов `.aqk/`;
   - проверка: `make aqk`, `make check`; через временную цель/параметр `make`
     выполнить только read-only `doctor --run`, `vitals`, `probe`, `report`.
5. Разобрать каждый красный исход и завершить лог.
   - файлы: этот план и обязательная карта;
   - проверка: у каждого отказа есть причина и следующий конкретный шаг.

## 5. Признаки приёмки

- П-1: npm и официальный тег подтверждают `0.10.0`;
- П-2: `Makefile` и CI закрепляют одну и ту же версию;
- П-3: новый `doctor --run` действительно запускает объявленные гейты и оставляет
  проверяемый отчёт;
- П-4: новые диагнозы не переписывают код, правила или реестры долга;
- П-5: полный `make check` зелёный либо каждый независимый красный исход назван.

## 6. Вопросы к тестам

- В-1: «новый AQK понимает текущую `.aqk.yml` без миграции?» — проверяет
  `doctor` и `vitals`;
- В-2: «каждый объявленный гейт по-прежнему исполним?» — проверяет
  `doctor --run` через `make`;
- В-3: «новые `probe/report` дают факты, а не меняют проект?» — проверяется
  снимком `git diff` до и после.

**Бюджет:** две строки закрепления версии; продуктовых строк и зависимостей нет.

## 7. Границы

- читать: metadata npm/GitHub, changelog, `.aqk.yml`, команды AQK;
- менять: `Makefile`, `.github/workflows/ci.yml`, этот план, `dock/README.md`;
- не трогать: продуктовый код, тесты, `tools/gates/`, реестры долга и
  `agent-ui-kit`; не выполнять пишущие команды AQK;
- тесты: только через `make`.

## 8. Арбитр

Version-check до/после, `make aqk`, `make check`, read-only `doctor --run`,
`vitals`, `probe` и итоговый `git diff`.

## 9. Наблюдаемость

В логе остаются версия, URL источника, команды, коды выхода и все красные
причины. Секреты не нужны; сетевой отказ отделяется от отказа гейта.

## 10. Риски

- выпуск опубликован во время аудита → версия сверяется непосредственно перед
  изменением;
- новый AQK предлагает миграцию → не принимать автоматически, вынести развилку;
- Windows выбирает WSL-launcher вместо Git Bash → запускать `make` в Git Bash и
  записать эту несовместимость отдельно, не выдавая её за дефект гейтов.

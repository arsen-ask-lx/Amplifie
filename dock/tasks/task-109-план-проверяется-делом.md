- **Как показать без кода:** `make trace-audit PLAN=task-108` печатает таблицу

## 4. Как делаем

1. **`tools/agent/trace-rules.mjs`** — чистые правила без файловой системы:
   - `claimsIn(plan)` — что план заявил: строки таблицы «Прочитано»
     и старая форма «Прочитано целиком: `a`, `b`» (для планов до task-109);
   - `coverageOf(events)` — какие строки каждого файла открыты: чтение
     инструментом по `startLine/numLines/totalLines`; `cat файл` — целиком;
     `sed -n 'a,bp' файл` и `head -n N файл` — диапазон; `grep` — фрагмент;
     перекрывающиеся диапазоны складываются;
   - `verdict(claims, coverage)` — по каждому «целиком»: да / частично (доля) /
     не открыт. Файл, названный одним именем, сопоставляется по концу пути;
     два кандидата — «неоднозначно», а не «да».
2. **`tools/agent/trace-audit.mjs`** — запуск: находит сессию (последняя
   по проекту либо `SESSION=`), берёт события **до последней записи плана**
   (заявление сверяется с тем, что было к моменту его написания), печатает
   таблицу и выходит с кодом 1 при расхождении. `make trace-audit PLAN=…`.
3. **`.claude/agents/plan-critic.md`** — инструкция владельца (читать
   файлы целиком, KISS/DRY/SOLID, связанность, масштаб на 5000, «чинить или
   переделать», варианты, долг), инструменты только на чтение, отчёт
   `файл:строка — вес — сценарий — исправление`, ничего не правит.
4. **`tools/checks/check-plan-review.mjs`** + чистое правило и тест:
   план с номером от 109 и статусом не «черновик» обязан иметь разделы
   «Прочитано» (таблица, каждый путь существует), «Варианты» (не меньше
   двух строк) и «Разбор критика» (каждое замечание — «принято» или
   «отвергнуто» с причиной). `make plan-review`, объявлен в `.aqk.yml`
   и потому идёт в `make check`.
5. **`plan-quality`** — маршрут: черновик → `make trace-audit` → критик →
   правка и разбор в плане → владельцу.

## 6. Признаки приёмки — чем докажем

- **П-1 ложь найдена:** `make trace-audit PLAN=task-108` помечает
  не прочитанными целиком не меньше 5 из 9 заявленных файлов
  (`readMarks.ts` открыт на 80 строк, `service.ts` — только поиском);
  `useReading.ts` и `unread.ts` — «целиком». Арбитр — ручная сверка трёх
  строк с записью сессии, а не сам скрипт.
- **П-2 без ложной тревоги:** чтение одного файла двумя кусками, покрывающими
  его весь, засчитано как «целиком» (точечный тест).
- **П-3 правило гейта:** план без разбора критика со статусом «одобрен» —
  красный; черновик без разбора — зелёный; старый план (до 109) — не проверяется
  (5 случаев в тесте).
- **П-4 гейт в конвейере:** `make check` запускает `plan-review` (строка
  в выводе AQK).
- **П-5 критик ловит то же:** разбор task-108 критиком называет расхождение
  «прочитано» с делом хотя бы в одном файле — без подсказки.

Числа до кода: сейчас ложь в «прочитано» ловится 0 раз из 1 известного
случая → цель 1 из 1; ложных тревог на двух тестовых образцах — 0.
SLO строкой: план не доходит до владельца без сверки с делом и без разбора
свежими глазами.

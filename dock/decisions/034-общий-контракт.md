# Р-034. Общий контракт на zod-схемах

| | |

| **Связано** | [04-каркас](../04-каркас.md) (обещал «REST + OpenAPI из тех же схем») · [task-039](../tasks/task-039-чистка-чата-и-проектов.md), шаг 3 |

## Решение

**Схемы запросов и ответов лежат в `packages/contract`** — zod, одна
на дверь. Бек и фронт импортируют одно и то же объявление.

**Сервер проверяет по ним через `@fastify/type-provider-zod`** —
официальный провайдер типов Fastify (преемник `fastify-type-provider-zod`,
перенесён в организацию fastify). Схема на маршруте проверяет тело,
параметры пути и строку запроса И сериализует ответ: лишнее поле
в ответ не просочится, а обработчик получает типизированный запрос.

**Фронт берёт типы через `z.infer`** — без генерации файлов. Сменился
ответ сервера — фронт перестаёт собираться там, где читает старое поле.

**OpenAPI не выпускаем сейчас** (YAGNI): провайдер тянет `@fastify/swagger`,
и `openapi.json` получается из тех же схем одной настройкой — когда
понадобится документация наружу или фаззинг дверей (schemathesis).

## Почему не другое

| Вариант | Почему нет |
|---|---|
| **OpenAPI + генерация типов** (`openapi-typescript`) | лишнее звено: схема → файл → сгенерированные типы. Генерированный файл отстаёт от кода, и нужен ещё гейт «файл свежий». С общими схемами типы берутся напрямую |
| **ts-rest** | последний выпуск — июнь 2025, требует zod 3; у нас zod 4. Брошенная зависимость — будущий долг |
| **tRPC / oRPC** | RPC вместо REST: пришлось бы переписать все двери, поток SSE, пороги частоты и 160 приёмочных, бьющих по REST-адресам. Это переписывание, а не шаг |
| **оставить как есть** | типы `Message`, `Conversation` написаны дважды руками — на беке и на фронте; сверяет их только глаз (task-039, класс 5) |

## Чем платим

- новая зависимость на беке и её соседи (`@fastify/swagger`, `openapi-types`);
- zod попадает в граф фронта — но только типами (`import type`), в сборку
  не едет, пока фронт не начнёт проверять ответы сам;
- правило: схема ответа описывает ВСЁ, что дверь отдаёт; забытое поле
  не уедет к клиенту — это и защита, и новый способ ошибиться.

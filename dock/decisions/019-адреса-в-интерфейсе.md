## Что произошло

Раздел интерфейса хранится в состоянии компонента:

```ts
const [section, setSection] = useState<Section>("talk");   // ChatScreen.tsx
```

Следствия, каждое проверяемо в браузере:

- **в строке всегда `/`.** Ссылку на задачу, разговор или договорённость дать нельзя;
- **«назад» не работает.** Кнопка браузера выкидывает из приложения целиком;
- **обновление страницы возвращает в «Разговоры».** Где бы человек ни был;
- **агент завёл задачу — показать её нечем.** В чате появляется «Завёл задачу
  „…"», и это тупик: перейти к ней можно только руками через доску.

Последнее — не косметика. Продукт про то, что агент делает работу, а
результат работы не имеет адреса.

Отдельно: переход по цитате (`openAt`) уже реализован и работает **только
внутри сеанса**. Механизм «показать нужную реплику» есть, а сослаться
на неё снаружи нельзя.

## Решение

**`react-router` 8.3.1, объявительный вид (declarative mode).**

Из трёх видов React Router берётся самый простой:

| вид | что добавляет | нам |
|---|---|---|
| **объявительный** | сопоставление адреса с экраном, `<Link>`, `useNavigate` | **да** |
| данных | `loader`, `action`, `useFetcher` | **нет** |
| каркасный | плагин Vite, серверная отрисовка, файловые маршруты | **нет** |

**Почему не вид данных, хотя документация советует его для SPA.** У нас
уже есть свой путь доставки: звонок по SSE и догон по номеру через
`/v1/sync` ([Р-006](006-живые-обновления.md)). Загрузчики маршрутов —
второй путь к тем же данным, и Р-006 отказался от второго пути ровно
потому, что два пути расходятся молча. Загрузчик, тянущий ленту при
переходе, разошёлся бы с догоном при первом же разрыве связи.

### Почему не wouter, хотя он в семь раз меньше

Честно взвешено. `wouter` 3.11.0 — 2.2 КБ сжато против ~15 КБ у React
Router, и всё, чего у него нет (загрузчики, серверная отрисовка, файловые
маршруты, вложенные раскладки), нам не нужно **сегодня**.

Перевесило другое:

1. **владелец дважды сформулировал предпочтение** — «лучше использовать
   готовые решения, чем самим всё делать»; в паре «мейнстрим против
   минималиста» это довод за мейнстрим;
2. **тринадцать килобайт — шум** на фоне 45 КБ, которые мы только что
   осознанно приняли в [Р-018](018-набор-компонентов.md). Отказываться
   от экосистемы ради 13 КБ после этого непоследовательно;
3. **соседний проект владельца уже на React Router.** Одинаковая
   маршрутизация в двух его проектах — реальная экономия внимания.

Довод про размер остаётся записанным: если когда-нибудь вес фронта станет
настоящей задачей, `wouter` — первый кандидат на замену, и переход стоит
день, потому что берётся тот же набор хуков.

### Какие адреса

```
/                       → Разговоры (последний открытый)
/c/:conversationId      → разговор
/c/:conversationId/:seq → разговор с подсветкой реплики (переход по цитате)
/board                  → Доска
/board/:taskId          → задача с её обсуждением
/deals                  → Договорённости
/agents                 → Агенты
/?invite=<токен>        → уже есть, остаётся как есть
```

Адрес приглашения не трогается: он читается один раз и тут же вычищается
из строки, чтобы не осесть в истории браузера. Это отдельное поведение,
и маршрутизатор ему не мешает.

## Что это стоит

- **+~15 КБ сжато.** С учётом Р-018 фронт становится ≈ 135 КБ;
- **`?invite=` и маршруты живут рядом.** Токен читается до отрисовки
  маршрутизатора, иначе `replaceState` подерётся с его историей.
  Это записано шагом в плане, а не оставлено на внимательность;
- **состояние `section` исчезает.** Раздел теперь выводится из адреса,
  а не хранится вторым источником правды. Это не цена, а выигрыш:
  сегодня их могло быть два.

## Сторож этого решения

Само по себе наличие маршрутизатора ничего не гарантирует: раздел можно
продолжать держать в `useState` рядом. Поэтому в плане назван проверяемый
признак — **`useState<Section>` не существует, а приёмочная проверка
открывает `/board/:id` прямым переходом и видит задачу.** Не «работает
навигация», а конкретный адрес, набранный в строке.

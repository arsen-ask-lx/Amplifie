# Р-002. Текст сообщения

| | |
|---|---|
| **Статус** | ✅ принято 2026-09-06 |
| **Почему сейчас** | необратимо: поменять форму потом = переписать все накопленные сообщения |
| **Связано** | [06-разбор-мессенджеров](../06-разбор-мессенджеров.md) · [04-каркас](../04-каркас.md) |

## Решение

**`message.body` — одна строка: исходный текст с разметкой (markdown).**
Разметку разбирает и рисует **клиент**. Второго представления (HTML, JSON-блоков)
на сервере нет.

## Как у других

| | Что хранят |
|---|---|
| **Discord** | обычный текст с разметкой, рисует клиент |
| **Zulip** | исходный markdown; HTML кешируется отдельно как производное |
| **Slack** | свой `mrkdwn`; для сложного — JSON-блоки |
| **Matrix** | **два** поля: `body` (текст) и `formatted_body` (HTML) |

Большинство хранит исходник. Двойное представление у Matrix — следствие федерации:
чужой сервер должен получить что-то, что нарисует любой клиент. **Мы не федерируемся,
и платить за это вторым полем незачем.**

## Почему исходник, а не HTML или блоки

**① Агенту нужен чистый текст — и он получает ровно то, что написал человек.**
Если хранить HTML, каждый прогон начинается с раздевания разметки, а это лишний
шаг, который иногда врёт. Если хранить структурный документ — агент читает
не текст, а дерево.

**② Цитаты. Это главный довод.**
У нас есть `citation` — «на чём основано утверждение агента», и в ней позиция
цитаты внутри сообщения. Позиция обязана указывать на **стабильную** форму.
Хранишь исходник — позиция вечна. Хранишь HTML или рендеришь на сервере —
любое изменение рендера сдвигает все накопленные цитаты, и метрика «доля
выдуманного» тихо портится.

**③ Одно представление не может разъехаться со вторым.**
Matrix обязан держать `body` и `formatted_body` согласованными. Два источника
правды об одном факте — то, что мы запретили себе принципом SSOT.

**④ Рендер на клиенте стоит ноль серверного времени** и не требует кеша,
инвалидации кеша и фонового пересчёта при смене правил разметки.

## Чем платим

- **Поиск идёт по исходнику**, а значит по тексту с символами разметки.
  Для полнотекстового поиска Postgres это несущественно (`**жирный**` найдётся
  по слову «жирный»), но точные фразы через разметку не найдутся. Порог
  пересмотра: когда поиск начнёт врать — добавить производную колонку
  с очищенным текстом. Она **производная**, поэтому обратима.
- **XSS — на стороне клиента.** Рисовать разметку обязан безопасный разборщик;
  вставлять сырой HTML в страницу запрещено. Это правило, а не пожелание:
  гейт — запрет `dangerouslySetInnerHTML` в коде фронта.

## Что решение НЕ фиксирует

Какой именно диалект разметки. Это **обратимо**: подмножество можно расширять,
пока не ломается уже написанное. Начинаем с самого узкого (жирный, курсив,
код, ссылка, перенос строки) и расширяем по надобности.

## Как проверяется

- гейт: `dangerouslySetInnerHTML` в `apps/web` роняет сборку;
- приёмочный тест: сообщение с разметкой сохраняется и возвращается **байт
  в байт тем же**, что отправил клиент.

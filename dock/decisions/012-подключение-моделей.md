## Главное, что выяснил ресёрч, — и это меняет постановку

**«Как делают другие сервисы» — это ровно то, что запретили.**

19 февраля 2026 Anthropic прямо запретил «использование подписочной
OAuth-аутентификации для любых сторонних продуктов, инструментов
и сервисов», а токены подписок Free, Pro и Max — «во всех контекстах
за пределами Claude Code и Claude.ai».

OpenAI формулирует мягче, но в ту же сторону: их собственная
документация советует вход по ChatGPT для интерактивной работы,
а для автоматизации — ключ. Дословный признак: **сидит человек
и смотрит — вход по подписке; машина работает без присмотра — ключ.**

Значит «подключить подписку» в лоб — то есть взять чужой токен и ходить
им в чужой API из нашего кода — сделать **нельзя**. Не «рискованно»,
а запрещено, и запрет свежий.

## Решение

**Два пути, и они устроены принципиально по-разному.**

### ① По подписке — запуском ОФИЦИАЛЬНОГО клиента

Мы не держим токен, не пересылаем его и не ходим в чужой API. Мы
запускаем на машине владельца его же `claude` или `codex`, который
уже авторизован его подпиской, и читаем ответ.

Запрос делает **сам Claude Code**, то есть та поверхность, которая
из запрета исключена. Это ровно тот сценарий, под который Anthropic
и завёл `claude setup-token`: их документация называет его средством
«для конвейеров, скриптов и сред, где браузерный вход невозможен».

### ② По ключу — обычным HTTP

Ключ из консоли, оплата по токенам, никаких ограничений на без­надзорную
работу. Для Codex это прямо рекомендованный способ автоматизации.

### Граница, которую нельзя переходить

| | подписка | ключ |
|---|---|---|
| своя установка, свой владелец, свои разговоры | ✅ можно | ✅ можно |
| **хостинг для чужих команд через одну подписку** | ⛔ **запрещено** | ✅ можно |

Второй столбец — единственный, на котором можно строить продажу
продукта как услуги. Подписка остаётся способом **своей** работы:
дёшево, предсказуемо, с потолком.

Это записано здесь, чтобы в тот день, когда появится первый чужой
арендатор, никто не «просто переключил провайдера».

## Устройство

```
agent/model/
  provider.ts   один интерфейс: спросить → получить текст
  cli.ts        подписка: запуск чужого клиента, чтение stdout
  http.ts       ключ: обычный запрос
  choose.ts     что настроено, то и берём
```

**Ядро об этом не знает.** `kernel/work` получает уже услышанное;
провайдер живёт в `agent/`, который выбрасывается целиком.

### Что здесь опасно и как закрыто

- **Запуск постороннего — это исполнение кода.** Команда берётся
  **только** из настроек сервера, никогда из запроса и никогда
  из сообщения. Оболочка не используется: аргументы передаются списком,
  подстановки нет;
- **Текст сообщений уходит в подсказку модели.** Ответ модели — данные,
  и данными остаётся: он становится текстом договорённости, который
  человек читает и подтверждает. Никакая часть ответа не исполняется
  и не превращается в команду;
- **Токена подписки мы не видим.** Он лежит там, где его положил чужой
  клиент, и читается только им. Утечка нашего дампа его не раскрывает;
- **Долгий ответ — не зависание.** У запуска есть срок; вышел — ошибка,
  а не молчание.

## Чем платим

- **Подписке нужна машина с установленным клиентом.** Это годится для
  своей установки и не годится для облака. Названо прямо, чтобы
  не выяснилось на продаже;
- **Одноразовый токен подписки живёт год и не обновляется сам.**
  Истёк — агент замолчал. Нужна проверка живости, а не догадки:
  для этого заведена команда `make model`;
- **Два пути — две поверхности отказов.** Оправдано тем, что первый
  бесплатен при существующей подписке, а второй единственный законен
  для чужих арендаторов.

## Как проверяется

`make model` спрашивает настроенного провайдера и печатает ответ.
Не «настройки выглядят правильными», а **живой ответ модели**: иначе
неотличимо, работает подключение или нет.

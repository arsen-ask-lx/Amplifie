# Р-001. Язык и рантайм

|---|---|
| **Статус** | ✅ принято 2026-09-04 |
| **Решает** | владелец |

## Решение

**Продукт пишется целиком на TypeScript.** Один язык от базы до кнопки:
Node 24 на сервере, React на клиенте, схема и валидация Zod, тесты Vitest.

**Python в рантайме продукта не появляется**, пока не сработал один из триггеров ниже.
Когда сработает — входит **отдельным сервисом за HTTP**, параллельным узлом,
и никогда вторым рантаймом внутри монолита.

**Python как инструмент разработки разрешён без ограничений** — скрипты, обработка
выгрузок, прогон эвалов, разбор логов. Это не рантайм продукта.

## Почему

**Один язык — это не вкус, а арифметика связанности.** Типы ходят от таблицы до
экрана без единой границы, где их надо переобъявлять вручную. Одна схема Zod
обслуживает разом HTTP-контракт, форму события и разбор ответа модели — это DRY
ровно по границам системы.

**Второй язык в монолите удваивает всё, что придётся понимать и сторожить:**
два дерева зависимостей, две сборки, два раннера тестов, два набора гейтов,
две уязвимые поверхности для supply-chain. При данности «один владелец, код пишут
агенты, владелец обязан понимать контракты» это прямой техдолг.

**Ни одна задача первых двух волн Python не требует.** Проверено по списку:

| Задача | Чем закрывается без Python |
|---|---|
| позвать модель | HTTP-запрос |
| расшифровка встреч | vexa по HTTP — это её язык, не наш |
| поиск по смыслу | `pgvector` в том же Postgres, эмбеддинги внешним API |
| аналитика и дашборды | SQL |
| дешёвый отсев для К1 | булево выражение |

**Различие, из-за которого обычно и заводят второй язык зря:** чужой сервис на Python
за HTTP — это **не** Python в нашем стеке. Мы его не собираем, не тестируем
и не обновляем ему зависимости. Для нас это URL.

## Триггеры, при которых Python входит

Только эти четыре, все про «считаем сами вместо того, чтобы звать чужое»:

1. модель работает на своём железе (локальный инференс);
2. эмбеддинги считаются в объёме, при котором внешний API дороже своего счёта;
3. появилась тяжёлая обработка данных — например, обучение классификатора
   на собственной переписке;
4. понадобилась научная библиотека, у которой нет аналога в экосистеме JS.

## Лестница выбора — останавливаться на первой ступени, которая работает

```
1. HTTP к внешнему сервису          → 0 новых рантаймов, 0 узлов
2. Расширение Postgres (pgvector)   → 0 новых рантаймов, 0 узлов
3. ONNX прямо в Node                → 0 новых рантаймов
4. Сервис на Python за HTTP         → +1 узел, обязательно параллельный
```

Ступень 3 обычно забывают: маленькая локальная модель-классификатор запускается
через `onnxruntime-node` прямо в Node, Python для этого не нужен.

## Как именно входит, если войдёт

- **отдельным сервисом за HTTP**, со своим образом и своим жизненным циклом;
- **параллельным узлом, не последовательным**: сервис лёг — чат и задачи живут,
  пропала только та функция, которую он даёт. По Люссеру последовательный узел
  умножает надёжность вниз, параллельный — нет;
- контракт между ним и нами — обычный OpenAPI, как со всяким чужим сервисом.

## Чем платим

- **Экосистема машинного обучения в JS беднее.** Если понадобится что-то за пределами
  вызова модели по HTTP, обходной путь будет длиннее, чем на Python;
- **однопоточность Node**: одна тяжёлая синхронная операция блокирует цикл событий.
  Мера — тяжёлое выносится в воркер или в отдельный сервис, а не пишется в обработчике;
- **соблазн «тут по-быстрому на питоне»** остаётся всегда. Против него и написано
  это решение: правило есть, и отступление от него — вопрос владельцу, а не
  решение в моменте.

## Как проверяется

Гейт в сборке: в образе продукта нет интерпретатора Python и нет файлов
`*.py` вне каталога `scripts/`. Нарушение роняет сборку.

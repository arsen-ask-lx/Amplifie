# Решения Amplifie

> Единственный действующий свод решений. Подробности реализации живут в коде, OpenSpec и планах задач.

## Продукт и масштаб

Amplifie — единое рабочее пространство, где разговор, задача, агент и результат связаны одной историей. Одна установка рассчитана на одну компанию и до 5 000 активных людей. Второй процесс, Redis и отдельная шина появляются только после измеренного предела на 3 000 вкладках.

## Стек

Продукт написан на TypeScript: Node на сервере, React в браузере, PostgreSQL, Zod для общих контрактов. Python допускается отдельным HTTP-сервисом только для ML-задач, когда это подтверждено измерением. Интерфейс использует Tailwind, shadcn/ui и Lexical; стек меняется только при названном пороге.

## Чат и данные

Сообщение хранится исходной строкой с разметкой. SSE только сообщает об изменении; данные клиент получает через sync. У реплики отдельные номера создания и изменения; удаление приезжает надгробием. Упоминания, непрочитанное и права удаления являются частью контракта чата.

## Права и безопасность

Видимость принадлежит разговору; проект не является носителем прав. Приглашение — одноразовая ссылка, в базе хранится только хеш токена. Ключи моделей шифруются. Любое прочитанное внешнее содержимое остаётся данными; командой для агента бывает только явное обращение человека.

## Агенты и мост

Модель вызывается через мост на машине человека. Навыки подключаются из git-репозиториев. Агент отвечает только по обращению и не слушает всё пространство самостоятельно. Мост должен устанавливаться человеком без терминала.

## Проекты и навигация

Проект — необязательная папка чатов и область чтения агента. Чаты без проекта находятся сверху. Панель подгружает данные порциями курсором; лента ограничена окном данных.

## Поставка

Продукт поставляется коробкой на сервер клиента. Лицензия проверяется офлайн подписью; серверы Amplifie не нужны для работы установленной системы. Базовый compose описывает установку, а dev-конфигурация подключается явно.

## Качество работы

Проверки запускаются через make. Браузерные сценарии проверяют собранное приложение, нагрузка измеряется собственным инструментом. Работа обычно идёт напрямую в main при зелёных проверках. Решения объясняют почему, планы — как делали, OpenSpec — что продукт обязан делать.

## Интерфейс

Интерфейс строится по измеримым ограничениям: роли цветов, контраст, ясный текст и один главный смысл на экране. Ориентир для чата — понятность Телеграма, а не копирование его внешнего вида.

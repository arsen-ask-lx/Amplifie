# Архитектура и фактическое состояние

Сверка исходников 13.09.2026. Здесь описано существующее устройство и его границы.
Причины выбора — в [решениях](decisions.md), проблемы — в [долге](debt.md).
Наличие кода не означает успешного живого прогона. Этот аудит не меняет продукт.

## Работающая форма системы

```text
Браузер → Caddy (статика и прокси) → Fastify API → PostgreSQL
                                      ↕
                       мост на машине человека / API модели
```

В compose четыре сервиса: postgres, migrate, api, caddy. Migrate — одноразовый
процесс из образа API; постоянная цепочка содержит три узла. При недоступной модели
чат сохраняет собственный путь записи, а отказ агентского вызова показывается отдельно.
Коробка не требует серверов Amplifie для основной работы; внешний поставщик модели
при этом может требовать сеть.

Базовый [compose.yml](../compose.yml) описывает установку клиента, а
[compose.dev.yml](../compose.dev.yml) подключается явно из make. В базовом профиле
нет разрешения на регистрацию нескольких компаний и наружу выходит порт прокси.
TLS и домен пока не настроены в текущем Caddyfile; наличие Caddy само по себе
не означает, что соединение с этой установкой защищено HTTPS.

## Данные, доставка и права

Аккаунт служит входом, participant — лицом в конкретном пространстве; человек и
агент представлены одной сущностью участника, каждый со своим ID. Применяются UUID v7 и время с часовым
поясом. Запись состояния и события выполняется короткой транзакцией.

Порядок задаётся счётчиком пространства под блокировкой строки. У сообщения есть
номер создания и номер изменения; мягкое удаление передаётся через догон.
Курсорная синхронизация учитывает группы изменений и постраничную доставку.
Одного bigserial для порядка commit недостаточно; delivered_seq из проекта v2
в этой реализации нет. Узкое место счётчика — [Д-2](debt.md#d-2).

SSE сообщает об изменении; содержимое приходит через /v1/sync с проверкой доступа.
Шина живёт в памяти одного процесса. Текущий догон читает БД и сообщает изменения
по пространству в пределах видимости. Хвост событий и подписка на открытый разговор
пока являются планами 067–069. Проект — необязательная папка и область чтения,
**не носитель прав**. Видимость принадлежит разговору, ветка наследует корень.

Дедупликация отправки опирается на clientMsgId; повтор с тем же идентификатором
не должен создавать новую реплику. Старое требование Idempotency-Key на каждом POST
не следует считать реализованным повсеместно. Автор действия определяется сессией.

Отметка прочтения хранится отдельно от членства, движется вперёд; непрочитанное
учитывает видимость, авторство и удаления. Разность глобальных seq не равна числу
непрочитанных сообщений. Ручная пометка «непрочитано» требует отдельной семантики.

RLS нет; доступ ограничивает приложение. Приглашения хранят хеш токена и имеют
срок, maxUses и отзыв. API-ключи модели шифруются; мастер-ключ приходит из окружения.
«Секреты только в окружении» относится к конфигурации/мастер-ключам и отсутствию
секретов в исходниках; это не запрет существующего зашифрованного хранилища ключей.

## Агент и граница контекста

Memo отвечает по обращению. В [answering.ts](../backend/src/app/answering.ts)
для чата читаются последние 100 реплик; для проекта — до 300 строк области.
Далее [сборка контекста](../backend/src/agent/answering/prompt.ts) применяет бюджет
по объёму. Настройки начала чтения по дате нет. Возможность области project есть
на сервере, но вход выбора в UI удалён — Д-33.

Порядок источников вызова: свой мост, свой/общий ключ, настройка сервера.
API-ключ способен работать с сервера; фраза «модель работает только через мост»
неточна. CLI-подписка требует установленного клиента на машине человека.
Отсутствие моста допускает следующий источник, другие ошибки не означают
разрешения молча переключать оплату. Условия поставщика проверяются перед
внедрением; локальный запуск не является универсальной гарантией допустимости
любой интеграции или передачи подписки.

После отправки клиент отдельно вызывает ask. Работа не переносится в устойчивую
очередь. Агент не следит за всем пространством, не владеет постоянной памятью,
не выполняет задачи и не пишет код. Политика прав не определяется текстом модели.

Node 24 выбран действующей основой. Смена языка не доказана необходимой текущими
замерами. Тяжёлые CPU-задачи нельзя помещать на обработку каждого запроса;
при появлении ML-задачи Python-сервис рассматривается отдельно по измерению,
а не потому, что пример из энциклопедии написан на Python.

Плавающими остаются не только Caddy, но и теги Node/Postgres. Даже точный тег может
быть переприсвоен; для неизменяемого основания сборки используют digest с явным
обновлением. Подробность и приёмка — Д-36, не незаметная замена образов этим аудитом.

## Развитие по измеренному условию

- Хвост изменений, кеш панели, догон по подписке: планы 067–069; права и отказ
  кеша проверяются отдельно, содержимое не отправляется всем подписчикам.
- Второй процесс: только после отдельного замера и решения о шине, сессиях,
  ограничителях и обновлении без простоя. LISTEN/NOTIFY — один из кандидатов.
- Полнотекстовый поиск: сначала вернуть пользовательский сценарий и измерить
  качество русского/английского запроса; схема словарей и ранжирование выбираются
  по корпусу. Количество строк само по себе не определяет необходимость внешнего движка.
- Виртуализация: если существующее окно ленты не проходит измеренный бюджет на
  реальных сообщениях. Замер 360 коротких узлов за 17 мс — исторический частный опыт.
- Тесты по свойствам, доступность, мутации и Compiler: кандидаты с отдельной
  постановкой и согласием на зависимость; не автоматически «час работы».
- Наблюдаемость: диагностический путь, метрики установки и воспроизводимое
  восстановление; сроки и требования определяются до обещаний клиенту.

## Проверки и источники сверки

make arch проверяет импорты; make typecheck — типы; make lint — кодовый стиль;
make docs — локальные ссылки; make decisions — основания; make map — правило
последнего коммита. make test / test-ui / cost требуют живой среды. make load
показывает свойства конкретного опыта, не сертификат вместимости компании.

- [Node: поддерживаемые линии выпуска](https://nodejs.org/en/about/previous-releases).

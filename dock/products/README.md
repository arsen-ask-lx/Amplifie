## 1. Что вообще есть в наличии

Поправка к бизнес-ТЗ: список продуктов оказался другим, чем записано.

| Продукт | Что это | Язык | Лицензия | Скачано |
|---|---|---|---|---|
| **paperclip** | пульт управления штатом агентов | TypeScript | **MIT** | исходники, 7 832 файла |
| **multica** | доска, на которой работают агенты | Go + TS | ⛔ **своя лицензия: запрет размещённого сервиса** | исходники, 5 375 |
| **buzz** | пространство, где люди и агенты в одних комнатах | Rust + TS | **Apache-2.0** | исходники, 29 297 |
| **plane** | классический трекер | TS + Python | **AGPL-3.0** ⚠️ | только развёртывание, 3 файла |
| **huly** | замена Notion + Slack + Linear | — | EPL-2.0 | только развёртывание, 140 файлов |

**Главное открытие по составу:** три продукта из списка описывают себя ровно вашей фразой
из бизнес-ТЗ — «агенты там, где люди работают». Это не пустая ниша, там уже стоят проекты
на 30–80 тысяч звёзд.

## 2. Сводная карта: у кого что есть

Четыре свойства, из которых состоит замысел Amplifie.

| | Чат между **людьми** | Задачи с доской | **Агент слышит без вызова** | Голос |
|---|:---:|:---:|:---:|:---:|
| **paperclip** | ✗ | ✓ | ✗ | ✗ |
| **multica** | ✗ | ✓ | ✗ | ✗ |
| **buzz** | ✓ | ✗ | **✓** | ✓ |
| **plane** | ✗ | ✓ | ✗ | ✗ |
| **huly** | ✓ | ✓ | ✗ (агентов нет вовсе) | ✓ |
| **vexa** | ✗ | ✗ | ✗ | ✓ (только расшифровка) |

**Ни одной строки с четырьмя галочками.** И это не случайность — это две разные школы,
которые пока не встретились:

- **трекеры с агентами** (paperclip, multica) выросли из доски задач. Разговор им не нужен:
  человек печатает задачу, агент её делает. Их «чат» — это консоль управления агентом
  (`role: user | assistant`), а не канал команды;
- **мессенджеры с агентами** (buzz) выросли из переписки. Задач как сущности нет —
  есть проекты, процессы и git-issue;
- **huly** единственный собрал чат + задачи + видео, но **агентов у него нет вообще**,
  и стек из шестнадцати контейнеров.

### Как именно агент узнаёт, что пора работать

Это самая важная строка всего разбора, потому что тут ваш К1.

| Продукт | Чем запускается агент | Проверено по |
|---|---|---|
| **paperclip** | расписание (сердцебиение ~30 мин), поручения, конвейеры, сторожа, назначение. Из 13 значений `originKind` человек — только `manual` | код |
| **multica** | `@упоминание` или команда `/issue`; автопилоты — только расписание, вебхук, вызов API. Прямая цитата их документации: «сообщения без упоминания бота **никогда не запускают агента** и не добавляются в его контекст» | код + документация |
| **buzz** | **правила подписки**: область каналов (`"all"` или список), виды событий, `require_mention: bool` — **необязателен**, булево выражение по тексту сообщения | код |
| **plane / huly** | нечем | — |

**Вывод:** механизм «агент слушает канал и решает сам» существует ровно в одном месте —
в `buzz`, в файле `crates/buzz-acp/src/filter.rs`. И он реализован правильно: дешёвый
детерминированный отсев выражением (100 мс, предкомпиляция, отключение правила при
серии тайм-аутов) **до** того, как позвали модель. Иначе слушающий агент разоряет по деньгам.

Но это механическое совпадение по выражению, а не понимание. **К2 — «отличить
договорённость от болтовни» — не решён нигде.** Дыра, которую вы нащупали, настоящая.

## 3. Реестр приёмов к применению

Всё, что стоит забрать. Сгруппировано по нашим звеньям К1–К5.

### К1 — агент слышит

| Приём | Откуда |
|---|---|
| правила подписки с необязательным упоминанием | buzz |
| дешёвое булево выражение до вызова модели | buzz |
| тайм-аут 100 мс, предкомпиляция выражения, отключение правила при серии тайм-аутов (fail-closed) | buzz |
| `prompt_tag` — агент знает, какое правило его позвало | buzz |
| гейт `ignore_self` — не реагировать на себя | buzz |
| `self_trigger_suppressed` — то же на уровне отправки | multica |
| ворота автора: владелец ∪ список ∪ братские агенты | buzz |
| схлопывание заявок на пробуждение (`coalescedCount`) | paperclip |
| ровно-однократная обработка входящего `(installation_id, message_id)` + токен захвата | multica |

### К2 — отличить договорённость от болтовни

| Приём | Откуда |
|---|---|
| очередь решений с правилами наполнения (`seedRules`) | paperclip |
| обучающие примеры решений: слепок + отсечка + исход + заметки | paperclip |
| вычистка удалённых комментариев из обучающих данных | paperclip |
| автоматическое обнаружение дублей и извлечение из внешних источников | quackback (по описанию) |

### К3 — сформулировать задачу

| Приём | Откуда |
|---|---|
| приёмочные критерии полем задачи, а не прозой | multica |
| у задачи поле ссылок на контекст | multica |
| «агент пишет описание перед созданием» (так у них сделано только для Slack) | multica |

### К4 — человек подтверждает

| Приём | Откуда |
|---|---|
| «решение» как объект: варианты с **машинными эффектами**, а не свободный ответ | paperclip |
| обязательный срок годности решения + статус «истёк» | paperclip |
| снимок состояния + `staleness: strict` — ответ на устаревший вопрос не применяется | paperclip |
| подпись спецификации решения (HMAC, ключ `0600`, сравнение с равным временем) | paperclip |
| ключ идемпотентности — ответ не применится дважды | paperclip |
| политика продолжения: кого будить после ответа | paperclip |
| опасный вариант выглядит опасно (`style: destructive`) | paperclip |
| `Steer` / `Interrupt` в работающего агента | buzz |

### К5 — задача уносит контекст

| Приём | Откуда |
|---|---|
| `issue_source_context`: слепок обсуждения + отпечаток + жизненный цикл `pending → attached / abandoned` | multica |
| инварианты состояния выражены `CHECK`-ами в базе | multica |
| `originKind` / `originId` / `originFingerprint` + таблица идемпотентности создания | paperclip |

### Сквозное: ответственность, безопасность, деньги

| Приём | Откуда |
|---|---|
| **разделение originator (чьей властью) и accountable (кто отвечает)** | multica |
| восемь источников ответственности + `Precise()`: точный или выродившийся | multica |
| выродившаяся привязка **помечена, а не спрятана**; «человек никогда не выдумывается» | multica |
| режим fail-closed: нет ответственного человека — запуск отклонён | multica |
| ответственность наследуется вниз по цепочке, **права — нет** | multica |
| `responsibleUserId` отдельно от исполнителя | paperclip |
| пять полей «кто сделал»: тип · человек · агент · **прогон** · **ключ доступа** | paperclip |
| одна подписанная форма события для человека и агента | buzz |
| карантин недоверенного источника: урезанные инструменты, результат в карантине, явные границы, повышение — действие человека | paperclip |
| `review_policy: not_creator` — кто сделал, тот не принимает | paperclip |
| бюджет и потраченное — поля самого агента; автопауза на 100% | paperclip |
| память агента приватна паре «агент↔владелец» (шифрование, адресация по HMAC) | buzz |
| эфемерные события не сохраняются вовсе | buzz |
| каталог кодов отказа в отдельном пакете-листе; коды не выдают существование приватных объектов | multica |
| единая лента внимания с сортировкой по срочности решения, а не по свежести | paperclip |

### Принципы, а не приёмы

- **«Агент должен быть достаточно мал, чтобы держать его в голове. Если не можешь
  проследить отказ от симптома до причины за минуты — система слишком сложна»** (buzz).
- **«Нет абстракций, отложенных на будущую гибкость»** (buzz) — совпадает с вашим
  «никогда на вырост».
- **Код причины решается там, где принято решение, и доносится дословно; он никогда
  не восстанавливается обратно из строки ошибки** (multica).

## 4. Чего НЕ повторять — чужие ошибки

| Ошибка | Где | Урок нам |
|---|---|---|
| ⚠️ Регистрация по умолчанию позволяла самому себе выдать доступ уровня доски **без администратора** (CVE-2026-41679); плюс выполнение команд через импорт вредоносного агента | paperclip | самообслуживание в регистрации и импорт чужих агентов — опасные места по умолчанию |
| Зашитый промпт выдаётся за «движок процессов»; сообщество называет это «не ядро оркестрации, а шаблон исполнения по умолчанию» ([#815](https://github.com/multica-ai/multica/issues/815)) | multica | не выдавать умолчание за настраиваемость |
| Ворота одобрения числятся известным ограничением; `send_dm` и `set_channel_topic` возвращают «не реализовано»; у реле **нет боевого ограничителя частоты** | buzz | одобрения и ограничение частоты нельзя оставлять «на потом» в продукте, где действует агент |
| 16 контейнеров и 5 чужих серверных систем | huly | закон Люссера: каждый последовательный узел множит ненадёжность вниз |
| Бесплатная установка ограничена 12 пользователями; AGPL | plane | лицензия и ограничения — бизнес-решение, принимать сознательно |
| 20 таблиц вокруг задачи и 10 под среды исполнения | paperclip | это обвязка «агент сам делает работу», то есть **ваша вторая часть** |

## 5. Что это меняет в открытых вопросах

**В-1 (Huly / Plane — форк, куски или своё).** Вопрос поставлен на устаревших данных.
Настоящая развилка теперь не «plane или своё», а «какая из трёх агентских основ».
Формальные признаки:

| Основа | Язык | Лицензия | Чего не хватит |
|---|---|---|---|
| paperclip | TypeScript ✓ | MIT ✓ | **весь разговор между людьми** |
| buzz | Rust ✗ | Apache-2.0 ✓ | задачи с доской |
| ~~multica~~ | Go ✗ | ⛔ **запрещает** размещённый сервис | — отпадает как основа |
| plane + своё | Python/TS | AGPL ⚠️ | вся агентская часть |

**Multica отпала.** Её лицензия прочитана целиком: Apache-2.0 плюс запрет
использовать код, чтобы «предоставлять размещённый сервис третьим лицам» или встраивать
в коммерчески распространяемый продукт — **независимо от того, берёте ли вы плату**.
Публичный экземпляр для людей вне вашей организации требует коммерческой лицензии,
даже бесплатный. Это ровно то, чем Amplifie является по замыслу. Подробный разбор —
[02-multica.md §8](02-multica.md). Как источник идей multica остаётся; как основа — нет.

Из оставшихся: по совпадению языка и лицензии впереди **paperclip**, по совпадению
замысла — **buzz**.
💭 Решать по признакам на бумаге нельзя, но развилка теперь описана честно.

**В-2 (первый срез).** Разбор подтвердил: сквозной сценарий «сообщение в канале →
агент предлагает задачу с контекстом → человек подтверждает» **не реализован нигде**.
Это и есть кандидат в первый срез — не потому что он маленький, а потому что он ваш.

**В-3 (где идёт разговор).** Multica уже ходит в Slack, Telegram, Lark, DingTalk, WeCom —
и делает это через `@упоминание`. То есть путь «прийти в чужой чат» протоптан, механика
приёма входящих (дедупликация, аудит, доставка) описана в коде и её можно списать.

**В-4 (агент — роль или инструмент).** Три разных ответа, и лучший — у multica:
не «роль или инструмент», а **два разных человека за каждым действием** — чьей властью
и кто отвечает. Плюс режим, где действие без ответственного просто не выполняется.

**В-5 (голосовые встречи).** Закрывается покупкой, а не стройкой: **vexa** — открытая,
Apache-2.0, самостоятельно размещаемая, приводит бота в Meet / Teams / Zoom, отдаёт
расшифровку в реальном времени с разделением по говорящим, через обычный HTTP.
Тяжёлую часть В-5 писать не нужно.

## 1. Красные проверки

Правило проекта: сначала проверка, которая падает, потом реализация. Все
проверки этой группы обязаны быть КРАСНЫМИ до второй группы — красноту
подтверждает прогон, а не намерение.

- [ ] 1.1 Тест «правка доезжает до второй вкладки» в `backend/tests/stream.e2e.test.ts`: участник догнал до курсора, автор правит реплику, следующий догон возвращает её с новым текстом. Проверка: тест падает на текущем коде
- [ ] 1.2 Тест «удаление приезжает надгробием»: догон возвращает запись с тем же идентификатором, `deleted: true` и БЕЗ поля `body`. Проверка: тест падает
- [ ] 1.3 Тест «догон не задваивает»: два вызова подряд без изменений между ними — второй ответ пустой. Проверка: тест падает или зелен по случайности, и в обоих случаях остаётся в наборе как страховка от задвоения
- [ ] 1.4 Тест «чужая переписка не просвечивает»: правка в закрытой переписке, где участник не состоит, не двигает его курсор и не появляется в его догоне. Проверка: тест падает
- [ ] 1.5 Тест «правка старой реплики не теряется за новыми»: сто реплик после неё, правка первой, догон возвращает первую. Проверка: тест падает
- [ ] 1.6 Тест «первичная загрузка не показывает надгробий»: список реплик переписки после удаления не содержит ни реплики, ни надгробия. Проверка: тест зелёный уже сейчас и обязан таким остаться

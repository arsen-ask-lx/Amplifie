# api/contract

## ADDED Requirements

### Requirement: Описание API совпадает с поведением дверей

Описание API SHALL собираться из тех же схем, которыми двери проверяют вход и
выход, и MUST NOT расходиться с кодом: устаревшее описание роняет быстрые проверки.
Каждая дверь, кроме потока событий и метрик, SHALL описывать успешный ответ и
отказы, которые она отдаёт.

#### Scenario: Схема двери поменялась, описание — нет
- **WHEN** поле убрано из схемы ответа без пересборки описания
- **THEN** `make check` красный с подсказкой `npm run openapi`

### Requirement: Неверный ввод — отказ, а не поломка

Дверь MUST отвечать 422 с полем, где ошибка, на ввод, не отвечающий схеме, —
включая нулевой символ в тексте, объект или число вместо строки, адрес почты вне
RFC 5321/1035. Ответ 500 MUST NOT нести текст ошибки или запроса к базе.

#### Scenario: Нулевой символ в названии папки
- **WHEN** человек заводит папку с `\u0000` в названии
- **THEN** ответ 422 с полем `title`, в ответе нет текста SQL

### Requirement: Незнакомый метод на известном пути — 405

На путь, который есть, с методом, которого у него нет, сервер SHALL отвечать 405
с заголовком `Allow`, перечисляющим методы этого пути. На путь, которого нет, —
404.

#### Scenario: PUT на «кто я»
- **WHEN** запрос `PUT /v1/me`
- **THEN** ответ 405 и `Allow: GET, HEAD`

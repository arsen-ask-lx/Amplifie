# Оснастка

Здесь лежат проверки и оснастка разработки. Они не входят в готовое клиентское
приложение. Стадия сборки фронта копирует `tools/dev` и настройки TypeScript;
это не означает, что они работают в итоговом контейнере Caddy.

| Каталог | Что внутри | Как запускается |
|---|---|---|
| `checks/` | свои проверки: ссылки документации, источники решений, контраст, ритм, сырой HTML, карта, связь с моделью | `make docs` · `decisions` · `decisions-check` · `contrast` · `rhythm` · `no-raw-html` · `map` · `model` · `gates` |
| `arbiter/` | счётчик согласия К2: корпус реплик, каппа Коэна, отчёт | `make arbiter` · `arbiter-check` · `label` |
| `gates/` | вшитые записи каталога AQK — чужой код, у каждой красный и зелёный образец | `make gates` — прогон `aqk doctor --run` по `.aqk.yml` |
| `ratchets/` | реестры принятого долга: число нарушений может падать, но не расти | читается гейтами |
| `load/` | свой нагрузочный прибор (Р-026) и рядом `load/k6/` — второй, независимый (Р-051): двери чтения с порогами, образ потока | `make load` · `make k6` · `k6-sse` · `k6-compare` — по живому стенду |

Плюс четыре файла настроек, которым нечего делать в корне:

| Файл | Чем читается |
|---|---|
| `vitest.acceptance.ts` | `make test` — приёмочные по живому стеку |
| `vitest.unit.ts` | `make unit` — быстрые проверки чистых функций |
| `dependency-cruiser.cjs` | `make arch` — границы модулей |
| `tsconfig.base.json` | общие настройки компилятора, наследуются всеми приложениями |

**Почему не все.** `biome.json` остаётся в корне не по привычке, а по отказу:
вне корня Biome считает конфигурацию вложенной и падает с «Found a nested root
configuration». Проверено. Там же и по той же причине живут `.aqk.yml`,
`compose.yml`, `tsconfig.json`, `.dockerignore` — их ищет по корню сам инструмент.

## Что здесь можно и чего нельзя

- **Запускать только через `make`.** Прямой вызов `node tools/checks/…` работает,
  но не является интерфейсом проекта: путь однажды поменяется, а `make` — нет.
  Именно поэтому пути живут в `package.json`, а не в голове.
- **`gates/` руками не форматируется.** Каталог исключён из Biome (`biome.json`):
  красный образец обязан остаться красным, а форматирование правит тот самый файл,
  на котором арбитр доказывает, что ловит брак.
- **Список гейтов не выдумывается здесь.** Он читается из `.aqk.yml` — единственного
  места, где объявлено, какие проверки у проекта есть. Второй список разошёлся бы
  с первым, и оба стали бы врать.
- **Проверка без подсаженного нарушения не считается работающей.** Гейт, который
  никогда не краснел на нашем коде, не отличим от гейта, который молчит.
- **У гейта карты два входа, и это не дубль.** Хук `commit-msg` из `.githooks`
  не даёт сделать коммит; `make map` смотрит на последний и потому переживает
  `--no-verify` и чужой клон, где хуки никто не включал. Хук удобнее, конвейер
  надёжнее; порознь каждый дырявый. Правило у обоих одно — `checks/map-rule.mjs`,
  чистая функция с подсаженным нарушением в `map-rule.test.mjs`.

## Оснастка для работы руками (`tools/dev/`)

В продукт не попадает — как и всё в `tools/`.

- **`make dev`** — фронт со своим сервером и горячей перезагрузкой на
  http://localhost:8477 — тот же адрес, что у собранного стенда. В `make up` фронт собран и запечён в образ: правильно
  для стенда, невыносимо при работе руками. **`make dev-api`** — то же для бека
  (Node 24 запускает TypeScript сам, сборки нет вовсе).
- **`make demo`** (`demo.sql`) — канал с диалогом на троих: посмотреть ленту,
  когда говорит не один человек. Дев-данные, стираются вместе с базой.
- **`make scale-seed`** — добавляет в выбранное dev-пространство помеченный
  нагрузочный набор панели: 100 проектов, 5 140 чатов внутри и 100 «Недавних».
  Запуск идемпотентен; `make scale-check` сверяет состав. По умолчанию это
  пространство задаётся явно: `SEED_WORKSPACE_ID=<uuid> make scale-seed`.
- **«Тыкалка»** (`agent-ui-kit`, подключён в `frontend/vite.config.ts`) — Alt+наведение
  подсвечивает элемент, Alt+щелчок открывает поле для замечания. Замечание
  ложится в `dock/reference/ui-notes.md` вместе с цепочкой компонентов и классами,
  по которым строка находится одним поиском. Файл в git не попадает.

## Почему `@types/react` объявлен в корне

Не по ошибке. Пакет значков (`@phosphor-icons/react`) поднимается npm
в корневой `node_modules`, а его объявления типов импортируют `react`.
Разрешение идёт от места самого пакета — то есть от корня, — и типов
фронта оттуда не видно: `IconProps` теряет всё, что наследует от `svg`,
и любой `className` у значка становится ошибкой типов.

Лечится одной строкой в корневых зависимостях. Гейт мёртвого кода считает
её лишней (её никто не импортирует), поэтому она названа в `knip.json`
явно — с этой причиной.

## Chrome DevTools для агента

`.mcp.json` в корне подключает **`chrome-devtools-mcp`** — официальный
сервер Google, дающий агенту то же, что человек видит в панели
разработчика: сеть, консоль со стеками по исходным картам, трассировку
производительности, снимки памяти.

⚠️ **ЗАЧЕМ ОН НУЖЕН, ЕСЛИ ЕСТЬ СНИМКИ ЭКРАНА.** Снимок показывает, ЧТО
на экране, и молчит о том, ПОЧЕМУ. Мигание первой реплики в новом канале
я чинил дважды не там, пока не залез в сеть и не увидел `GET /v1/sync?after=0`
— четыре захода и 118 чужих сообщений ровно в тот миг, когда человек
печатает. Из кода это не видно, глазами — тем более.

Подключается при следующем запуске Claude Code. Ставится сам через `npx`,
в продукт не попадает.
